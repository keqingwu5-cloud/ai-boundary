# 主腦私人後端 V0.1（設計／開發骨架）

> **未部署、未接通三個 AI、未建立真實雲端記憶；不能當成已可正式使用的安全服務。**
> 這個公開 GitHub repo 只存程式、資料表及說明，不應放入使用者記憶、指令、API 金鑰、密碼、Token 或正式資料庫備份。

## 為什麼要獨立後端

目前 `index.html` / `feed.html` / `launcher.html` 使用靜態 GitHub Pages；原大腦圖譜與發射器草稿主要存在本機瀏覽器。公開站點本身**無法安全保存私人中央記憶或授權金鑰**。

私人後端可由另一個有授權控管的 Worker + D1 提供服務，但仍由同一主腦網站入口操作。資料庫必須設置為私人存取，不應寫入 `data.js` 等公開資料。

## 檔案

- `src/index.js`：隔離 API，採 Bearer Token 權限驗證；沒有秘密金鑰即回傳不可用狀態；禁止跨來源 OPTIONS。
- `migrations/0001_initial.sql`：任務佇列、記憶候選、獲核准的記憶紀錄、操作稽核事件。
- `wrangler.toml.example`：設定範本，不含實際 DB ID 或憑證。

## 路由草案

| 方法與路徑 | 權限 | 用途 |
| --- | --- | --- |
| GET /health | 驗證通過 | 檢視 API 可用性，不宣稱 AI 同步 |
| POST /tasks | 管理者 | 建立單／雙／三 AI 任務，狀態 queued |
| GET /tasks | 管理者 | 查詢近期任務與回報 |
| POST /tasks/claim | 特定代理 | 僅領取指派給該 AI 的任務（15 分鐘租約） |
| POST /tasks/:id/report | 領取代理 | 提交任務結果與踩坑紀錄；租約須有效 |
| POST /candidates | 管理者／代理 | 建立待審記憶，不直接寫權威記憶 |
| GET /candidates | 管理者 | 審核佇列 |
| POST /candidates/:id/review | 管理者 | 核准／拒絕候選；需要審核理由 |
| GET /memory | 管理者 | 已核准記憶 |
| GET /audit | 管理者 | 操作稽核 |

所有寫入記錄事件，三方身分仍須由真正的代理整合實作；**資料表有任務不代表外部 GPT 能自動領取**。

## 部署前的必要條件（尚未滿足）

1. 在私人環境建立 Cloudflare Workers 和 D1，將 `wrangler.toml.example` 複製為私有 `wrangler.toml`，設定真正的 DB ID 並執行 D1 migrations。
2. 使用安全的秘密管理設定 `ADMIN_TOKEN` 與 `AGENT_GPT1_TOKEN`、`AGENT_GPT2_TOKEN`、`AGENT_BOT3_TOKEN`，各自不同。**勿提交到 GitHub 或貼進聊天**。
3. 配置身份驗證／登入及「同來源安全代理」（BFF），由伺服器保存管理者憑證，**不可把管理者 Bearer Token 放入公開網站 JavaScript 或 localStorage**。
4. 明確審核 API 是否符合「只能由原提出者語意對齊後進入候選核准」：目前只保存狀態，尚未實作原提出者獨立確認與抗冒名證明。
5. 建立 rate limit、Token rotation、金鑰撤銷、資料加密與備份、資料保留／刪除規則、不可否認的審計紀錄、安全測試。
6. 建立逾期領取任務的恢復／重新指派；目前過期租約會維持 claimed，需人工處理。
7. 強化跨多筆 SQL 的原子操作，尤其「候選核准→寫入權威記憶→記錄稽核」的交易一致性。
8. 引入真正的 GPT②、BOT③ 執行橋接器，確認它們是否有定時接收、權限內執行與安全回傳的接口。
9. 寫入的內容可能不受信任；必須防止提示注入、外部來源冒充指令、超大回報導致資料污染。
10. 測試身分隔離、未授權存取、同時領取衝突、重試與重複事件、錯誤回復、記憶去重、修改原問題等流程後才能考慮正式部署。

## 發射器與後端的差別

- **現行發射器**：可以本機保存、匯入／匯出、分享／複製交接；無伺服器私有存儲、無真正 AI 自動發送。
- **此 PR 後端骨架**：有任務與候選記憶的 API 與資料表，尚未正式部署、未與前端連接。
- **未來正式主腦**：需要安全 BFF 代理、用戶登入、三方獨立憑證與執行橋接器、審核流程、端到端測試後才成立。

不應把 PR 合併等同於可安全運作。重大核心變更仍由使用者決定，其他 AI 不得靜默覆寫。
