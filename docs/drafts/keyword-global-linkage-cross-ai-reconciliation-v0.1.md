# 第一大腦｜關鍵字全域關聯與跨 AI 狀態對帳（雙方審閱草稿 V0.1）

> 狀態：DRAFT / REVIEW ONLY。僅供 GPT①、GPT② 閱讀、評論，不代表功能已實作、部署或驗收。

## 目標
輸入一個關鍵字或問題 ID，從共同索引自動找出相關歷史問題、需求、決策、修補、測試、阻塞、依賴、因果假設、BOT 研究與最新證據，產生一個**可分享的關聯檢視連結**，供雙方看到同一份可追溯資料。

## 入口與輸出
- 輸入：關鍵字、同義詞、任務 ID、Issue/PR、模組名稱或自然語言問題。
- 輸出：固定查詢 ID 的關聯頁面（未實作；URL 格式待雙方審查），包括關聯網絡、時間線、當前狀態、差異報告、原始證據連結。
- 一個關鍵字可關聯多個問題；同一問題維持永久 problem_id，避免更名或改字造成歷史斷裂。
- 搜尋結果分為「直接證據」「明確依賴」「語意相關」「待驗證因果」，不可把語意相似誤當已驗證因果。

## 自動關聯流程
1. 擷取問題實體、關鍵字、同義詞、任務 ID、版本與來源。
2. 從 GitHub Issues/PR/commit/CI、經授權的 Notion 與共同記憶索引檢索；保留權限隔離，不外洩私有內容。
3. 連接關係：same_problem、depends_on、fixed_by、regressed_by、tested_by、blocked_by、supersedes、possibly_related；每條邊有來源與信心／驗證狀態。
4. 依事件時間與來源版本產生歷史時間線；新資料追加，不覆寫舊證據。
5. GPT① 與 GPT② 各自提交具 task_id/event_id/attempt_id、執行者身分、commit、CI、測試範圍及可獨立回讀 ACK 的聲明。
6. 對帳器比較「已修復」「局部通過」「待驗證」「BLOCKED」「證據不足」「衝突」；輸出差異原因，不以單一 AI 自述直接改寫共同狀態。
7. 每次新修改前自動載入歷史錯誤、影響模組、未解決阻塞與回歸測試清單；修改後回寫新證據。

## 例子：查詢「GPT② 自動交接 ACK」
關聯候選：Issue #41、#54、#56，PR #42、#48、#49、#50、#52；PR #59 的信任邊界問題需標為「可能相關／待核對」，不能自動認定為 #41 的直接根因。
- 已有隔離 PostgreSQL 與合成 worker 測試通過紀錄。
- 這些測試不等於現有 GPT② ChatGPT 對話獨立、自動接收，也不等於可信 ACK 與真實 E2E。
- 若 GPT② 有更新成果，應先取得最新 commit、CI、實際接收證據，再逐項解除對應阻塞。

## 雙方審閱問題
- GPT①：歷史問題、依賴與驗收條件是否完整？哪些狀態應保留 BLOCKED？
- GPT②：最新修補及測試證據是否已納入？哪些是已完成、哪些只是候選？
- 雙方：共同問題 ID、事件格式、關聯邊種類、來源優先序、衝突解決及權限隔離是否可行？
- 現有兩個 ChatGPT 對話不應被假定可由 GitHub 自動喚醒；如採 API Agent 執行者，須與既有 GPT①／GPT② 對話明確區分。

## 最小驗收
- 相同關鍵字能穩定找回歷史與關聯，並有來源連結。
- 同一問題跨描述／同義詞能歸併，但不誤合併不同問題。
- 最新測試可更新子問題狀態，且不會錯誤解除整體阻塞。
- GPT①、GPT② 可閱讀同一份版本化差異報告；未取得真實 ACK 時顯示未驗證。
- 新修改自動帶出受影響模組與既有回歸測試；缺失清楚標記。
- 未授權的私人記憶與正式資料不得進入共享索引。
