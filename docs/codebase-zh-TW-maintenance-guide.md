# AI 主腦｜全程式碼繁體中文維護手冊 V1

> 目的：讓未來的 GPT①、GPT②、BOT③ 與人類維護者，不必先讀懂每一行程式，也能知道「功能在哪裡、為什麼存在、改動會影響什麼、怎麼驗證」。
>
> **重要：中文化的是說明、註解、介面及文件，不是把 JavaScript / HTML / CSS 的語法、API 名稱、資料欄位與既有識別碼任意翻成中文。** 否則會破壞程式、儲存資料及跨系統相容性。
>
> 本文件根據 2026-10-13 GitHub 主分支的檔案清單建立，屬「全庫檔案盤點＋維護入口」；尚不是逐函式完成的程式碼註解或逐行稽核。凡標為「需追查」的內容不可當成已驗證的內部實作。

## 一、三方責任與中文化標準

| 角色 | 任務 | 必交付 |
|---|---|---|
| GPT① 指令發號者 | 決定中文化範圍、優先序、完成條件，彙整記憶與驗收 | 每次變更的任務卡、影響範圍、驗收結果 |
| GPT② 反證審查者 | 檢查說明是否與原始程式一致，尋找漏掉的副作用、反例與拒絕原因 | 錯誤清單、反證、未完成與拒絕紀錄 |
| BOT③ 實作驗證者 | 新增繁體中文註解、文件、測試及必要的 UI 翻譯 | 修改差異、測試證據、失敗與回滾方式 |

任何 AI **不得**因為文件已建立，就宣稱功能已自動完成、已同步其他 AI 或已通過實機測試。

## 二、修改程式前一定要回答的六個問題

1. **功能**：這段程式對使用者做什麼？
2. **入口**：哪個頁面、按鈕、事件或 API 會啟動它？
3. **輸入／輸出**：讀取哪些資料、回傳或修改什麼？
4. **記憶／副作用**：是否修改 localStorage、加密記憶庫、歷史、GitHub 或其他資料？
5. **失敗／拒絕**：哪些條件會拒絕操作？失敗會留下什麼？
6. **驗收／回滾**：要跑哪些測試？若有問題如何恢復？

建議在重要函式上方使用：

```js
/**
 * 功能：〔用中文描述〕
 * 觸發：〔使用者操作或事件〕
 * 輸入：〔參數、來源、格式〕
 * 輸出：〔回傳值、畫面變化〕
 * 記憶／副作用：〔是否寫入或修改既有資料〕
 * 失敗處理：〔拒絕、回滾、備份與提示〕
 * 驗收：〔對應測試及人工操作〕
 */
```

## 四、記憶管理的最小商業紀錄

一筆任務只需要：**任務 ID、任務名稱、負責角色、狀態、證據／原因、下一步、時間**。

狀態以程式識別碼保存，畫面以繁體中文呈現：

| 程式狀態 | 中文意思 |
|---|---|
| `queued` | 待交接 |
| `received` | 已確認接收 |
| `in_progress` | 進行中 |
| `blocked` | 阻塞／未完成 |
| `refused` | 被拒絕 |
| `review` | 待驗收 |
| `done` | 已完成 |

拒絕與失敗必須保留**原始原因、時間、下一步**；不得為了讓報表漂亮而刪除。若只是未送達 GPT② 或 BOT③，狀態應保持 `queued`，不可寫成 `received`。

## 五、知識自動觸發：目前能做什麼

目前記憶管理頁在**本機記憶庫已解鎖**時，可以按問題文字做相關記憶回溯；輸入查詢或任務名稱時會觸發比對。搜尋結果需顯示「已核准／待審／被拒／任務進度」等狀態。

**不能聲稱已實現：** GPT② 或 BOT③ 自動讀取私人記憶、雲端同步、跨裝置授權、模型自主更新核心記憶。下一階段如要實現，需另建後端身分驗證、最小權限、資料加密傳輸、存取稽核及撤銷權限。

### 建議的後續自動觸發流程（設計目標，尚未全部實作）

```text
收到新任務
  ↓
辨識任務 ID、主題與使用權限
  ↓
只檢索已核准的知識（拒絕／未完成紀錄另列為警示）
  ↓
把來源、版本、時間與適用條件一併提供
  ↓
GPT① 決定是否發號，GPT② 反證，BOT③ 測試
  ↓
保存實際回報（含拒絕與失敗）
  ↓
產生新候選 → 人工核准 → 更新正式記憶
```

## 六、程式碼中文化的安全界線

**可以改：** README、維護文件、中文註解、使用者看得到的文字、錯誤訊息（保留可搜尋的錯誤代碼）、測試案例的中文說明。

**不可直接改：** HTML 元素 ID、CSS 選擇器、JavaScript 函式名稱、JSON 欄位、localStorage key、資料庫 schema、事件名稱、網址路徑、檔名、API、第三方函式庫、授權原文。

要重新命名技術識別碼，必須獨立提出遷移方案、相容測試及回滾；不能當作單純翻譯。

## 八、尚未完成與需追查

5. **尚未收集 GPT②、BOT③ 真正的未完成／拒絕回報。** 需要透過發射器人工交接或後續有授權的連接。
6. **第三方函式庫及媒體不屬於需要翻譯的程式碼。**

## 九、建議實作順序

**第一階段：** 記憶管理與發射器（`memory.js`、`memory-workflow-core.js`、`memory.html`、`launcher.html`）。

**第二階段：** 主腦節點與資料（`app.js`、`data.js`、`index.html`、`mainbrain.html`）。

**第三階段：** 世界模型與知識評估（`world-model.html`、`knowledge-score.js`、`feed.js`）。

**第四階段：** 音訊、影片、發佈腳本、版本與測試。

每階段：**原始程式盤點 → 中文說明 → GPT② 反證 → BOT③ 測試 → GPT① 驗收 → 記錄變更**。保持每次修改範圍小、可回滾。
