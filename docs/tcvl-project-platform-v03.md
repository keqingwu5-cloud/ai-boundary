# TCVL｜共用平台、專案治理與候選新版圖 V0.3

**狀態：Draft PR #28。這是一套本機互動的工作治理原型，不是已經連接三個 AI 的 SaaS。**

## 使用者如何操作

從主腦任一主要頁面上方的共用平台控制列，可以開啟：**專案治理、架構圖、發射器、回溯驗證、加密記憶審核**，以及**狀態／圖片設定**。

| 中心 | 接收什麼 | 做什麼 | 產出或交接到哪裡 | 沒有完成的部分 |
|---|---|---|---|---|
| 專案治理 | 專案目標、人工對話、任務、決策與候選模組 | 管理狀態、暫停工作、拒絕提醒、規劃路徑 | 工作空間 JSON、候選版圖 JSON、待審記憶包 | 不會自動接入 GPT①／GPT②／BOT③ |
| Launcher Hub | 使用者手動下達指令 | 建立及複製任務／回報包 | 人工交接至指定 AI，之後核對收件 | 無真實 API 任務取消／接收回執 |
| 架構導覽 | 模組清單、規劃中的候選版圖 | 顯示目的、輸入、作用、產出、驗證、交接與退回，並規劃路徑 | 未接線的淡化節點、路徑示意、完整架構候選記憶包 | 不會自動部署候選節點 |
| TCVL-04 回溯 | 測試用虛構資料 | 回看主張、反證、影響與修正前後對照 | 可人工審查的路徑和修正示意 | 仍未取得真實多 AI 交叉驗證 |
| 加密記憶管理 | 人工匯入架構／專案候選包 | 候選、拒絕、修復、核准、版本保存和唯讀歷史檢視 | 本機加密記憶，需密碼與人工審核 | 未有跨裝置雲端同步 |

## 1. 共用狀態規則

- 基礎任務狀態：**待交接、已確認接收、進行中、已暫停、阻塞／需協助、已拒絕、待審查、已完成（人工記錄）**。
- 全平台共用設定可以新增**狀態名稱**，每個自訂名稱要對應其中一個基礎狀態。例如「等待資料來源」可以對應「待審查」，不是讓系統自動宣稱工作完成。
- 專案治理的狀態下拉選單與本機記憶頁的人工工作紀錄，可以識別這些共用標籤。
- **接口連線狀態**（人工交接、本機審核、虛構展示、尚未接通）與**任務工作狀態**是兩種不同概念。使用者新增狀態名稱不會修改接口實際連線能力。
- 狀態名稱與圖片偏好只保存在目前瀏覽器的未加密 UI 設定中，請勿把敏感內容寫成狀態名稱。專案及私人對話不寫入該設定。

## 2. 停止工作，對話繼續

- 在選定專案建立任務與對話；任務、對話是兩份不同紀錄。
- 按**「停止指定工作」**時，只把被選任務標記為「已暫停」，並保存人工填寫的完成進度與狀態事件；其他工作不受影響。
- 暫停後可以照常在專案內**建立新對話、增加訊息、保存決策及待辦**。
- 按「繼續工作」可以從原進度恢復；任何舊紀錄應保留，不抹除原始進度。
- **限制：** 因為沒有真正的 AI 控制後端，停止鍵**不會停止 ChatGPT 這段對話，也不會取消遠端 API 執行、GitHub 任務或其他 AI 正在做的工作**。未來若接入遠端工具，須增加實際取消指令、回執與超時處理。

## 3. 拒絕／阻塞即時提醒

- 使用者在專案工作區記錄 **已拒絕／阻塞**，或拒絕**候選版塊**時，必須填寫**原因、可能受影響範圍、下一步**。
- 系統在這次事件被記錄後，立即在頁面上顯示醒目提醒；後續可以標記已閱，但不會把原始拒絕刪除。
- 在已解鎖的加密記憶管理中，拒絕候選或記錄拒絕／阻塞的人工進度**成功加密保存後**，也會出現當下提醒。
- 如果正在執行的其他 AI 沒有接線，平台不會冒充已經知道其拒絕／阻塞；此時需要人工帶回資料。

## 4. 圖片設定

共用面板提供：圖片**標準顯示、淡化／簡化、隱藏**，以及**完整顯示／裁切填滿**。這只是未來有圖片的介面可沿用的**視覺顯示選項**，不涉及生成圖片，也不是全站圖片資料庫；目前主要介面仍以節點與文字呈現。

## 5. 未來新版圖與路徑擴充

1. 在專案治理頁輸入候選模組名稱、作用、來源節點，新增後只顯示為**淡化的未啟用版塊**。
2. 使用者可以新增交接／分支／依賴關聯；舊連線不會覆蓋，重複線不新增，依賴關聯不能形成循環（交接路徑可以雙向）。
3. 候選可以**保留待審、拒絕、核准規劃**；即使核准規劃也不代表接口已部署或通過驗證。
4. 在同一專案中匯出「**候選新版圖 JSON**」，前往架構導覽頁按「匯入專案的未來候選版圖」。
5. 架構導覽只接受有指定 schema、節點與邊格式完整的檔案；匯入後增加淡化節點及「規劃中／未接通」的路徑，高亮路徑時能看到限制。
6. 之後可將完整架構產出為待審記憶候選包，透過加密記憶頁**人工匯入、審核及核准**；不能直接覆寫正式記憶。

**引用／依賴關係不等同因果證明。** 未來真正接線仍需要 API 權限、身份、回執、記錄及安全後端。

## 6. 專案與對話延續

- 一個專案包含：名稱、目標、人工建立的對話串、工作任務與狀態歷史、決策、待辦、候選節點、關聯、拒絕／提醒。
- 新對話沿用同一專案的目標、決策、待辦，不必放棄先前討論。
- **目前資料僅暫存在該網頁記憶體**。跨頁或關閉後若要繼續，須先**匯出工作空間 JSON**，之後再匯入。此 JSON 並未加密，可能包含對話與專案資料，請不要公開分享。
- 較短的工作空間也可產生符合現有記憶管理格式的待審候選包；但保留專案各個工作狀態的完整互動式復原，目前仍以 JSON 匯出／匯入為主，不能宣稱與加密庫自動雙向同步。
- 未來真正跨頁／多使用者延續，需要統一權限、獨立儲存後端和協作事件處理。
