# 第一大腦｜最小隔離試運行 V0.2 審查與發佈門檻

- 來源：PR #127，固定起點 HEAD `23d9845039a19015f671f512a1de4dba05c2f752`
- 本補丁：隔離 review 分支，**不是 main，也不直接更新 gh-pages**
- 目的：修正真正影響 V1.6「空白不得默認為零」與「證據須對應目前輸入」的前端問題，供使用者驗收
- 本版不增加任何正式資料來源／資料庫／憑證／外部 API，也不自動授權部署

## A. 發現與修補

| 問題 | 風險 | V0.2 處理 | 審查方式 |
|---|---|---|---|
| HTML 數值欄留空被 `Number('')` 視作 0 | 將 MISSING 變成有效數值 | UI 以明確的必填整數解析器拒絕空白；不得用 Number 直接轉空字串 | 清空 A、B、已選 KNOWN 的 C → 顯示「輸入錯誤」，不得產生/匯出 |
| 前次成功後修改輸入，舊 X/Y 和可匯出證據仍顯示 | 錯誤版次/舊證據被當成新結論 | 修改任何輸入立即清空 X/Y/來源/證據，停用匯出，必須重新執行 | 改變 B，確認 X/Y 清空且匯出停用，重算後才開啟 |
| 未知 C 卻對未使用的 c 進行數值檢查 | 隱藏欄位污染未知狀態 | 核心只在 C=KNOWN 時驗證其數值；UNKNOWN / INTENTIONALLY_OPEN 保持完整空白 | C 為未知、隱藏值無效亦不自動算出 Y |
| 容易誤解「重用 X」為持久化或跨 AI 共享 | 對部署能力產生不實期待 | 頁面明示每次重新建立隔離引擎，只在同一次流程內引用 X | 使用者於畫面可直接閱讀限制 |
| 未有外部連線禁止的實際瀏覽器網路攔截驗收 | 靜態頁可能誤載不必要的遠端資源 | Chromium review test 中若向 localhost 以外發請求即記錄並阻擋 | 同一 PR HEAD 的 Chromium CI 檢查 |

## D. 退回與停損
- 若 Pages 啟用後發現任何敏感資料請求、儲存寫入或輸入空白被當成零：先停止公開試用，停用 Pages 或將 `gh-pages` 恢復到經確認的安全版本；不要擅自覆寫或刪除私人資料。
- 若 CI 有任一 FAIL 或無法核對固定 SHA：狀態為 BLOCKED，不發布。
- `0` 是合法明確輸入；`''`、MISSING、UNKNOWN 不能直接換算成 `0`。
- 不將 GitHub Actions 通過稱為 Safari/iPad 實機通過；也不等於正式主腦、真正跨 AI 交接、長期持久快取的驗收。

## E. 使用者審查項目
1. 試用「清空 A」、「C 選 KNOWN 後清空」、「明確輸入 C=0」三個例子，判斷用語與行為是否符合預期。

3. 決定是否批准將此 V0.2 修補同步到 **僅合成資料的 gh-pages 試用站**。
4. 若要對外提供網址，應另在 GitHub Pages Settings 啟用分支託管，並執行公開網址連線及手機實機驗收。
