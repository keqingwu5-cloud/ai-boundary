# TCVL｜主腦全平台共用治理入口 V0.4（整批整合）

## 目標與設計界線

使用者希望在同一個主腦平台維持共同狀態、停止工作與對話分離、圖片設定、拒絕提醒、路徑擴充、未啟用版塊虛化、專案上下文及新候選版圖。以先補齊需求、再集中驗證為優先順序。

**不能將人工操作當成遠端 AI 自動連線，也不能將「規劃已核准」說成「接口已接通」。** 目前主腦部署在公開 GitHub Pages；專案／對話資料只在網頁暫存，離開前須匯出 JSON，真正持久化的私人記憶必須另經加密庫人工匯入及審查。

## 模組如何相互作用

| 模組 | 操作入口與具體作用 | 交接與限制 |
|---|---|---|
| 共用狀態 | 各主要頁面的「狀態／圖片設定」可新增狀態名稱，選擇原有的標準狀態類別；治理工作台可對任務套用顯示名稱。 | 自訂名稱不改變真實任務狀態；不能用名稱聲稱遠端 API 已連線。僅儲存狀態標籤與偏好，不儲存聊天。 |
| 共用平台入口 | 控制台、發射器、專案、三方中樞、架構、回溯、記憶管理都能切換。3D 大腦與短影音使用可收合入口，避免覆蓋主視覺。 | 專案與提醒不會在各網頁自動同步；有資料需先匯出／匯入。 |
| 停止指定工作 | 共用入口可前往專案治理工作控制；選擇任務、保存進度、停止／恢復。三方中樞也可停止單一角色的本機追蹤。 | 不影響其他任務或專案對話；不會遠端取消其他 AI 的執行。 |
| 拒絕與阻塞提醒 | 專案治理、三方中樞、記憶候選拒絕時，立即顯示原因、影響與下一步；對應頁面並可透過共用提醒顯示事件。 | 只有已在本頁記錄的事件能即時提醒；沒有監控尚未連接的外部服務。 |
| 圖片設定 | 共用入口可選正常顯示、灰階淡化、隱藏，以及完整顯示或裁切填滿；設定跨同來源主要頁面共用。 | 目前作用於一般 HTML 圖片，不等於關閉 3D Canvas 或短影音播放。 |
| 路徑擴充 | 可建候選節點、分支／依賴／交接規劃，並從專案匯出候選地圖，在架構圖匯入與檢視接口狀態。 | 候選路徑不覆蓋原關聯，且必須明確標示未接線。 |
| 版塊虛化 | 新增／審查中的規劃節點以低對比、虛線邊框表示。 | 虛化表示未啟用，不能等同已連線的實際執行節點。 |
| 專案與新對話 | 建立專案、對話、決策、待辦和手動工作紀錄，任務停止後仍可繼續討論。 | 目前不會自動呼叫 ChatGPT 或其他 AI；跨頁延續需 JSON 匯出與手動匯入。 |
| 未來新版圖 | 先建立候選，經人工審查後可轉為已批准的「規劃」，但仍保留原始分支和證據。 | 將來接線須經權限／安全／真實傳輸驗收。 |
| 主腦加密記憶 | 架構與專案匯出符合記憶候選格式，再在解鎖後人工匯入、核准或拒絕。 | 不直接把公開頁面的規劃寫入正式記憶；舊版與拒絕紀錄留存。 |

## 導覽順序

1. **發射器／主腦入口**：決定目標，產生任務或新對話。
2. **專案治理**：綁定工作、對話與待辦；停止指定任務，保留同一專案內的對話。
3. **架構圖**：查看模組作用、狀態、路徑及接口可用性。
4. **三方中樞**：分配三個角色的人工交接指令，記錄拒絕和測試回報。
5. **回溯視圖**：用虛構案例演示過去判斷、反證、影響與修正。
6. **記憶庫**：人工審查並保存架構與結果的核准、拒絕及版本鏈。

## 本輪補強：共用狀態、工作續接與設定同步

- 任務使用**基礎狀態與自訂顯示狀態雙軌紀錄**：新增 `displayStatusId` 作為自訂狀態穩定識別；舊標籤若在共用設定中移除，專案會顯示原始基礎狀態並註明舊標籤已停用。這不會自動改成「已完成」。舊版僅含 `displayStatus` 的記錄仍支援閱讀。
- 手動匯入的任務會檢查自訂狀態 ID 格式與對應顯示內容，不接受不合理的缺漏欄位。共用狀態清單仍透過既有規則驗證名稱、類別與重複。
- 共用**圖片偏好及自訂狀態清單**在同源且已開啟的其他瀏覽器分頁變動後會更新；不跨頁分享專案工作空間、對話、私人記憶或 API 金鑰。
- 三方中樞的共用停止入口會直接定位到該頁的「指定角色停止」區；其他頁面仍前往專案治理選定工作。**停止只暫停本機追蹤**，正常對話不會被關閉。
- 三方中樞在尚有未匯出的批次或資料室索引變更時，會嘗試在離開前提醒；即使已觸發 JSON 下載，也要自行確認檔案已確實保存，尤其手機瀏覽器不能保證離開提示一定出現。
- 共用狀態標籤屬於**工作進度**，而架構圖的「實作中／未接線」屬於**接口技術實況**。兩者不可互相取代，使用者自訂狀態不會讓尚未部署的接口顯示為已連通。

本輪仍依要求「先整批補齊，再集中驗證」，未新增第二套測試流程，並未修改現有正式加密記憶的儲存格式。
