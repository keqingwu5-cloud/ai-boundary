# TCVL｜條件式門檻與骨架建置規範 V0.1
日期：2026-10-16
狀態：**未合併、人工治理原型**。此文件先於門檻執行程式建立，後續變更需依同一批需求完成集中驗收。

## 0. 範圍鎖定
僅處理使用者指定項目：全平台狀態選項與接口、指定工作停止但對話繼續、圖片共用設定、即時拒絕提醒、路徑延伸、未啟用區塊虛化、專案新對話及續接、未來候選版圖、條件式篩選、開發前中後紀錄與門檻機制紀錄。其他想法一律先放候選清單，不自動追加到本批實作。

## 1. 門檻（Gate）的統一格式
任何由治理頁觸發的工作空間變更，建立明確的門檻紀錄，至少包含：
- `gateId`、`action`、`projectId`、`at`、`phase`（before／after／failure）
- 原始 `revisionBefore` 與結果 `revisionAfter`（失敗時僅紀錄更新本身升版）
- `conditions[]`：每項 `id`、`expected`、`actual`、`passed`、`required`、`description`
- `decision`：`pass`／`hold`／`reject`
- `reason`、`impact`、`next`（禁止空白）
- `source`：人工或未驗證匯入，不能偽裝成自動驗證。

門檻**通過只代表允許下一個操作或送交審核**，並不代表事實正確、AI 已收到訊息、接口已連線或正式記憶已核准。若必要條件未通過，阻止資料變更，保留拒絕原因、影響與可行下一步，立即提示。

## 2. 修改前、中、後的條件式篩選
| 階段 | 必須檢查 | 未通過處理 |
|---|---|---|
| BEFORE（建置前） | 需求是否在已核准範圍、原始專案／記錄是否存在、預期版次與目前版次一致、操作來源及權限聲稱是否有依據、必要欄位是否齊全 | 停在原狀態，產生 `hold/reject` 紀錄；不能直接寫正式記憶 |
| DURING（骨架變更） | 新增分支不刪除原關聯；暫停只影響選定工作不影響專案聊天；未接線接口不能標已送達；拒絕／阻塞必帶原因＋影響＋下一步 | 即時停止這次資料更新，保留失敗原因與原版本 |
| AFTER（變更後） | 更新後的資料結構有效、原有決策與任務未被無痕刪除、事件與版本新增並可回溯、工作任務沒有自行恢復、介面狀態清楚 | 整次更新回退到變更前的有效資料，另外寫入失敗的門檻紀錄 |
| MEMORY（記憶候選） | 匯出資訊需有來源、原因、版次與審核狀態；不得自動導入公開記憶或自行核准 | 只可輸出待審記憶包；使用者解鎖、匯入、比較、人工核准／拒絕 |

**一次修改產生 before 與 after 兩筆門檻事件；未通過仍會留下 failure 事件。** 拒絕提醒不是背景默默發生：介面要立即列出原因、影響與下一步，並保留在原專案。

## 3. 判斷下限與阻斷條件
- **關鍵阻斷：** 缺來源、找不到專案／任務、已存在重複 ID、版本落後、權限不足、嘗試把候選直接標正式啟用、把暫停任務直接標完成、把手動交接宣稱為已驗證 AI 回覆。
- **保持待驗證：** 部分資料齊全，但外部身分／證據未經驗證、接口仍為規劃或展示，此時不能輸出「完成／已連線」。
- **拒絕必須提醒：** 保留原始拒絕及修正候選間的關係，附下一步，不以關閉提示當作問題已解決。
- **門檻不可冒充證據：** `passed` 只是條件檢查結果，仍要區分人工填寫、靜態程式檢查、實測及未驗證證據。

## 4. 記憶更新條件與界線
- 主腦自己的**專案工作區記憶**：保留專案目標、決策、待辦、暫停狀態、對話索引、候選版圖、門檻／拒絕／修正事件；建議以帶版本的工作空間 JSON 封存並檢查版本。
- 主腦的**本機加密權威記憶**：僅經既有候選包匯入及人工審核後才新增／修正，拒絕保留理由；不能直接由公開架構頁操作。
- **ChatGPT／GPT 自身長期記憶**：網站無權直接改寫；只能生成「專案續接／記憶候選摘要」，供使用者審核並在有權限的對話或功能中使用。不能聲稱已自動同步 GPT①、GPT②、BOT③ 或本 ChatGPT 的記憶。
- 專案續接卡只摘要部分最近資訊；必要時使用完整工作空間封存，不能因為換新對話就忘記已停工的任務。

## 5. 集中驗收，不無限新增測試
先按此規則補完整個指定骨架，再做一次集中測試：門檻通過、條件缺失／拒絕、版本衝突、失敗回退、停止後對話續接、候選不變正式、拒絕立即顯示、記憶候選不自動核准。最後才做手機瀏覽器與真實加密庫的整合驗收。增加新需求前須由使用者明確授權。
