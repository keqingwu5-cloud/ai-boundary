## 0. 一句話總綱

第一大腦不只是「收資料 → 推理 → 派工」。它應能在可控權限下，追問每一個行動的原因、比較可能局勢、檢查過往經驗，並依真實觀測校正下一輪的認知。

**核心循環：證據 → 當前認知狀態 → 驅動／因果假說 → 可選行動與棋局推演 → 受控執行或停止 → 實際觀測 → 認知校準／記憶更新候選。**

「新的候選理解」與「已核准基準」必須分離。預測與實際、宣稱身份與已驗證身份、發送與真正 ACK、局部 CI 與正式部署不得混同。

## 1. 每個自動化節點都使用相同三軸認知接口

### 三軸

- **動機邏輯（Why）**：需要什麼？什麼驅動變化？限制在哪裡？為什麼選這種方法？人類的目的應區分「當事人明說」和「外部推斷」。物理現象應使用物理驅動與約束，不擬人化為意圖。
- **世界如棋局（What next / What if）**：局勢有哪些實體、關係、資源、規則、參與者、走法與可能反應？如果沿用／替代／反問／停止，各有什麼成本、風險、可逆性和連鎖後果？真實世界是不完全資訊的動態棋局，不是預知所有棋子的確定性棋盤。
- **記憶體（What did we learn）**：有哪些先前事件、失敗、核准、反證和策略？當時知道什麼、後來修正什麼？記憶應保存歷史版本、來源和未知，不因新的結論覆蓋原始紀錄。

### 十個流程節點與三軸應用

| 節點 | 動機／驅動問題 | 棋局／路徑問題 | 記憶問題 |
|---|---|---|---|
| 1. 感測與監測 | 為何有新訊號或異常？ | 影響哪個局部／整體局勢？ | 有沒有類似訊號及誤報？ |
| 2. 身份、授權、可信基準 | 誰提出改動、宣稱何種目的？ | 會不會改變權限或現行規則？ | 歷次核准和撤權是什麼？ |
| 3. 差異與問題辨識 | 根因／限制可能為何？ | 是局部變化還是依賴連鎖？ | 過去同類故障與已知反證？ |
| 4. 推理、反證、方向選擇 | 原本假設為何、可能偏差在哪？ | 沿用、替代、反問、停止、保留研究？ | 哪些方法曾被證實有效／失效？ |
| 5. 任務計畫與 Gate | 這件事為何值得做？ | 方案、資源、時程、風險、撤回成本？ | 過往估時、延期與風險評估？ |
| 6. Worker／BOT 受控執行 | 行動仍符合核准目標嗎？ | 局勢是否偏離預期、要暫停嗎？ | 記錄行為及對應版次，不冒稱已成功 |
| 7. 結果驗證與獨立審查 | 有何利益衝突或認知偏誤？ | 是否漏看替代路徑和外部效應？ | 對比失敗負例、歷史審查與已知缺口 |
| 8. 證明包與分類日誌 | 成敗、延期的候選原因是什麼？ | 哪個決策造成後續變化？ | 誰做／誰審、時序、來源、證據、版本 |
| 9. 通知與人類決策 | 為何這次需要人類介入？ | 不處理／批准／延後的後果？ | 人類核准、拒絕與理由的歷史 |
| 10. 記憶／世界模型更新與下一輪 | 哪項因果或目的假說需要修正？ | 新證據改變了哪些局勢邊？ | 保留版本化知識、舊假說與反事實 |

三軸並不是三次必須重跑的模型推理；它是每個節點「可按需要檢索和推演」的共同認知契約，不能因為三者一致就跳過授權 Gate。

## 2. 最小認知單位：有證據的狀態轉移，而非任務名稱

建議核心抽象：**Transition = 原始狀態 S0 ＋ 候選驅動與因果 ＋ 可選行動 A ＋ 預測 S1 ＋ 實際觀測 O1 ＋ 證據與校準紀錄**。

六種基本元素：
1. Entity（實體）：人、AI、工程模組、組織、設施、資料集、概念。
2. State（狀態）：版本、數值、位置、健康、權限、時間點。
3. Relation（關係）：依賴、影響、衝突、相關、候選因果；不可將相關直接冒充因果。
4. Drive（驅動）：需求、誘因、利益、物理作用、制度、約束；區分觀測、本人陳述和推論。
5. Action（行動）：執行、研究、反證、替代、暫停、停止及重新審查。
6. Evidence（證據）：來源、版本、時間、作者／操作者聲稱、驗證與反證。

**認知完整性規則：Predicted、Observed、Inferred、Unverified、Approved 為不同欄位或狀態，不得無聲互換。**

## 3. 動機邏輯的底層分解

以「需求 → 限制 → 選擇」三層解釋行動：
- 需求：系統／人／環境存在什麼問題或變化壓力？
- 限制：權限、資訊、技術、資源、時間、制度、自然法則如何限制？
- 選擇：為何採取某種方法？其他路徑成本、風險與效用？
每個原因都能附競爭假說、反向解釋和待查證條件。不得因為推論合理就將隱含動機寫成已驗證事實。

## 4. 棋局推演的底層資料結構

世界如棋局是**帶不確定性的動態狀態圖**：節點包含實體和狀態，邊包含關係和依賴，候選行動產生不同的未來分支；每個分支保留假設、資源條件、受影響者反應、可逆性和反證。

不是所有節點都有競爭者；對電力、水量、基建、資料品質，應採物理／技術／制度特有規則。對人類行動可建目的候選，但仍保留未知。

方向選擇器至少比較：REUSE、ALTERNATIVE、CHALLENGE_PREMISE、STOP、RESEARCH_ONLY；只產生建議，授權要由另一層決定。

## 5. 記憶體結構：三類記憶＋反事實

- **事件記憶**：何時、何事、誰聲稱執行／審查、原始證據與結果。
- **認知記憶**：當時的原因假說、因果候選、局勢推演、反證與可信程度。
- **程序記憶**：經驗證的操作方法、應避免的錯誤、回退或檢查方法。
- **反事實記憶**：當時未選的方案、為何不選、預測可能結果；未執行者不得寫成實際成果。

新結果形成更新候選，舊記憶應保持可追溯，正式權威記憶的寫入仍須獲得審查與授權；不得建立未治理的第二份記憶權威。

## 6. 時間結構：四個不同時鐘

- Event time：外部現象實際發生時間，若不明確就標 UNKNOWN。
- Observation time：系統何時觀測或擷取此資訊。
- Approval time：可信基準／政策何時正式核准（沒有核准就保持 NOT_APPROVED）。
- Revision time：何時提出對舊知識的修正，需保留舊版及理由。

支援「在某日期當時知道什麼」與「根據今天的新證據如何重新理解當時」兩種查詢。日誌的原定完成日、目前觀測日、延期預估日，是工作進度的獨立時間軸，不應取代上述證據時間。

## 7. 三條互相連動、但不可互相冒名的循環

1. **日常快速執行**：感測 → 差異 → 授權檢查 → 派工 → 驗證 → 記錄／通知。
2. **認知慢速校準**：新證據 → 三軸分析 → 多方向與反證 → 預測／實際比較 → 改進方法及知識候選。
3. **安全與恢復**：異常 → 停止／隔離 → 根因 → 補丁 → 獨立重測 → 真實恢復核准。

安全性（Safety）和活性（Liveness）需兼顧：既不能隨意越權，也不能讓所有合法工作永遠停在 HOLD。唯獨權限未驗證時不能為了進度而硬推。

## 8. 認知校準：不只記住錯誤，還要比較預測誤差

每次有意義的決策候選可保留：原始假說、預期結果、信心範圍、不確定性、關鍵前提、替代路徑、後續實測、偏差大小、原因候選、修正建議。

不能用「AI 自認有信心」代替校準。必須利用可比對的觀測與負例，檢查是否反覆高估工程整合、誤判時間或把相關誤讀為因果。

## 9. 成本與推理深度

- L1：無重大差異，依版本／指紋重用已驗證資料，少量檢查與紀錄。
- L2：發現衝突、延期、因果不清，啟動動機＋棋局＋歷史比對。
- L3：涉及高風險、可信基準、權限、重大認知矛盾，啟動獨立反證與人類審查。

每個階段應保留資料品質、計算成本、時間期限、不可逆風險及是否值得繼續研究的評估。這裡的「無限擴張」指開放式領域與組合、逐步增加知識；不是運算能力、時間或儲存真正無限。

## 10. 與可信控制循環、證明包及進度日誌的連接

**不新增第二個權限中樞。** 三軸是認知候選層；可信控制循環負責身份、基準、操作模式、派工權限、停止與真正 ACK 的審核。

每個重要候選事件應可連回：
- event_id、domain_id、source_ref、source_revision、source_hash、baseline_revision；
- 誰提出／誰操作／誰審查（區分身份聲稱和真驗證）；
- 事件／觀測／核准／修正時間；
- 動機、局勢、記憶引用；預測、實際、偏差、反證；
- 四類日誌：AUTOMATION、REASONING_SUMMARY、WORLD_MODEL、MEMORY；
- 各 project 的原定日期、預期進度、目前進度、延期原因、更新時間與預估完成日；
- 許可狀態、審查結果、實際回執狀態與下一步方向。

推理日誌只記可供審查的**結論摘要、依據、反證與決策理由**，不要求或保存模型隱藏的內部思考鏈。

上述連接目前是**研究規格**，不是宣稱 PR #133–#135 已有三軸完整實作或自動化真實接通。

## 11. 單一合成實驗（未執行，供日後評估）

基準 V10 已獲核准，感測器發現 V11：
1. 觀測 V11 與來源指紋；不得自行升格。
2. 動機：列出「為何有人想升級」的明示目的、可能驅動與可查證反證。
3. 棋局：比較保留 V10、測試 V11、局部更新、等待或停止的依賴和風險。
4. 記憶：查找先前失敗、相依元件、歷次審查和回退經驗。
5. 方向選擇器提出候選方案，但不自行批准。
6. 證明包與日誌記錄執行者、獨立審查者、預期／現況／延期日期與進度。
7. 必須有真實授權與獨立回執才能改動受保護基準；不具備時停在 HOLD/UNKNOWN。
8. 後續用實測與當初預測比較，產出認知校準及記憶更新候選。

## 12. 已知未解的基礎問題／審查清單

- 真正的身份信任根、核准者身份、授權和撤權如何建立？不能靠自產金鑰自行授權。
- 來源觀測與被核准的基準何時、由誰、以何證據銜接？
- 多 AI 的目的端是否確實獨立收件並返回可核驗 ACK？Issue #41 仍是獨立問題。
- 跨程序長期儲存、版本交易一致性、時鐘信任與備份如何驗收？
- 認知假說怎麼跟真實可觀測量對齊？如何避免假因果、假精度？
- 不同領域和專案能否共享結構但隔離資料、型別、權限及物理單位？
- 何時需要 L3 深推理，何時基於資訊價值主動停止？如何量測效益？
- 新知識何時只保留研究候選，何時可正式寫入權威記憶？誰真正批准？
