## 0｜主管一頁摘要（優先閱讀）

**最終目標：** 建立強化人的第一大腦的 AI 系統。人的角色是規劃與決策，不應是日常工作的人工派發員。候選區比較資訊價值、資料庫整理證據、第一大腦研發新模型、記憶體核心保存經核准的長期知識；所有有意義的行為都應可雙向回報。

**現在的交付：** 新增候選區的本機可操作原型、狀態表、上下文及記憶／因果關聯檢視、候選送審門檻，並延伸 AI 生態管理面板與手動雙向事件記錄。**沒有**直接接通三個 AI、私有 Supabase 規章、雲端核心記憶或內部自動驅動。

| 項目 | 有哪些能力 | 還不能宣稱 |
|---|---|---|
| 候選區 | 手動登記、比較重複、指出缺少來源與三鏈，分類為待補／送審 | 自動挖掘全網或直接收進核心 |
| 介面面板 | 顯示區域職責、已知限制、人工雙向回報 | 真正收到獨立 AI 的 ACK |
| 工作空間門檻 | 本機檢查版本、操作來源、範圍及歷史 | 已執行 23 條資料庫正式規章 |
| 候選規章 | 23 筆現存私庫候選；可手動匯入非敏感索引 | 23 條已生效或已自動同步 |
| 記憶核心 | 舊版另有本機加密記憶與人工審核 | 任一資料自動升級正式記憶 |
| 自動任務驅動 | 後期可依授權規劃 | 已部署任務投遞、遠端停止、接收與重試 |

## 1｜系統定位與資料流

| 角色 | 主要工作 | 資料進出 |
|---|---|---|
| 候選區／篩選員 | 像面試一樣凸顯資料亮點、辨識重複、保存反例 | 新資料進；產生待補、對照及送審候選 |
| 資料庫／資料管理員 | 自動化方向：整理上下文、版本、錯誤、修正、來源 | 經審查的資料進；受控索引及證據回傳 |
| 第一大腦研發中心 | 自由組合因果推演、競爭解釋、未知 X 與反證 | 索取證據；輸出新假設及反例，回到候選區 |
| 記憶體核心 | 保存經規劃者核准的關鍵長期知識 | 不接受其他模組越權直接寫入 |
| 任務傳輸管理員 | 未來負責安全派發、領取、雙向 ACK、停止及回報 | 真正接口尚未接線 |
| 規劃者 | 決定目標、重大例外與核准 | 不應手動處理所有日常微事件 |

**雙向原則：** 任何拒絕、反駁、修正、請求、正常執行或失敗，均需保留發起者、接收者、原事件、證據、回覆與下一步。資料發出不等於真實接收；回覆不同意也要保留。

### 2.1｜候選資料必須說明

- **基本欄位：** ID、版本、種類、標題、主張摘要。
- **知識亮點：** 此資料比舊資料多提供了什麼；不能為了通過候選審查而誇大。
- **上下文：** 適用時間、對象、目的、前提與來源。
- **記憶管理鏈：** 只能記授權的索引 ID，不能貼私人記憶明文；不適用須說明原因。
- **因果鏈：** 區分假設、證據和反證；純程序規章可合理標示「不適用」。
- **重複比較：** 類似文字不等於同一來源；多份轉載不等於多份獨立證據。
- **審查限制：** 候選就算通過資料檢查，也不能自動正式批准規章或升級核心記憶。

### 2.2｜四種候選門檻輸出

| 顯示 | 含義 | 處理 |
|---|---|---|
| 待補資料（hold） | 缺來源、亮點、比較、上下文或鏈關聯 | 補證、保留舊資料 |
| 可能重複（compare_duplicates） | 標題或摘要重複 | 比對獨立來源與實際新增價值 |
| 可送研發審查（research_review） | 有來源、可追溯且有研究或反證方向 | 第一大腦繼續探索；不等於已證實 |
| 可送資料庫審查（database_review） | 基本上下文及鏈已記錄，需資料管理員審查 | 分類和保存候選；不等於直接進記憶核心 |

**注意：** 本機門檻只代表「可以進一步人工審查」，不是真正的跨服務授權執行引擎。

### 2.3｜23 條候選規章的索引匯入

現有 Supabase 私有資料表中 23 條仍為候選，不在公開網頁放入原文。安全索引只允許規章 ID、版本、**確認非敏感**的標題，由有權限者自行匯出再手動載入候選頁。可參考 [虛構索引範例](../examples/tcvl-safe-rule-index.example.json)。

索引檔的 schema 識別是 **tcvl.safe-rule-index.v1**，records 陣列元素有 regulation_id、version、title 三項；不得加入私人內容、金鑰或規章正文。匯入後仍一律是待補證候選，不會直接修改資料庫或授權狀態。若連標題都敏感，不得進公開 repo。

## 3｜維護安全條件

- 本頁不向後端發送請求，也不會自動寫 Supabase；事件和候選資料只存在本次瀏覽器執行期記憶體，**離開前先人工匯出 JSON**。
- JSON 匯出檔未加密，不能保存私人核心記憶、API Token 或真實個資。
- 版本、反證、拒絕、過期資料不可無痕覆寫；人工記錄需帶來源和理由。
- 原有 23 條規章的 DB 狀態仍是 candidate；GitHub 的 R1～R4 核准紀錄與正式私庫版次不一致，不能自行轉換成已生效規章。
- PR #19 後端與 PR #27 備份相容性仍需獨立驗證；PR #28 不能因前端加頁面就假設安全接線。
- GPT① 和 GPT② 的原有暫停追蹤，及 BOT③ 004 的人工交接安排不因本次修改而取消。
- **沒有規劃者明示核准，不合併正式主分支、不部署、不改資料庫權限、不批准核心記憶或規章。**

| 項目 | 本輪結果 | 尚缺驗證 |

| 資料庫規章 → 正式執行端 | **未接線／未驗證** | 身份、有效版次、拒絕與放行、稽核的端到端測試 |
| 備份、權限、發布與回滾 | **未完成驗收** | 跨版本還原、正式 CI、部署核准 |

**正式驗收時至少檢查：** 缺來源必須 hold、同內容不同來源要人工比較、因果不適用必有理由、23 筆索引只能進候選、回覆來源不得冒充獨立 AI、候選不得越權批准、非法匯入需拒絕、瀏覽器重整前匯出與恢復必須實測。

## 5｜修改規格與交接紀錄格式

每次修改務必回答：**(1) 為什麼做、(2) 修改了什麼、(3) 哪些測試真的執行、(4) 哪些仍未完成、(5) 誰有權決定下一步**。交接須附工作 ID、GitHub commit、來源、證據、舊版本影響、反證及回滾條件，避免只有「已完成」三個字。

## 6｜下一步（按使用者的優先順序）

1. **候選區 P0：** 由具權限管理員補齊 23 筆非敏感索引及上下文關聯，規章衝突逐條判斷，不批量核准。
2. **平台 P0：** 使用本版頁面做人類可讀的候選／系統狀態管理與實機驗證，測試候選門檻、資料復原與雙向回報。
3. **門檻驗證：** 先確保本地候選／工作空間檢查不越權，正式規章政策引擎需待權威版本與後端權限確定才可以實作端到端。
4. **內部驅動後期：** 真實領取／ACK／停工及資料自動整理須用受控的後端和獨立身份，不能以手動 UI 假裝自動運作。
