# TCVL｜主腦架構治理中心與雙向紀錄 V0.2

> **原則：使用者先看懂用途、資料路徑、當前可用狀態與修正責任，不必閱讀程式碼。** 本文件與 \`architecture-hub.html\` 都是未合併的開發草稿，不是企業系統已上線證據。

## 1. 平台工作視角

整體流程：

**使用者／外部資料 → Launcher Hub → TCVL-01（資料治理） → TCVL-02（三方研究與反證） → TCVL-03（錯誤歸因、退回與重測） → 本機記憶審核 → TCVL-04（歷史回溯） → 新候選回到資料治理。**

此處是**工作與引用關係圖**，不是自動通訊已完成的因果證明。每個模組可以點選，並展開以下資訊：

| 欄位 | 使用者能看見什麼 |
|---|---|
| 用途與狀態 | 解決問題、目前是部分實作／示範／規劃 |
| 輸入 | 接收哪些問題、任務、候選、證據與版本 |
| 處理 | 審核、研究、反證、條件測試或影響掃描等操作 |
| 輸出 | 任務包、候選、測試報告、修正計畫、記憶版本 |
| 驗證 | 哪些結果仍待事實／身份／權限／實機查核 |
| 下游 | 誰需要接收這個結果、如何交接 |
| 反向退回 | 哪種失敗、附什麼證據、應退回什麼角色 |

使用者可在架構圖同時看每個節點的狀態標示。路徑規劃會高亮路徑中的節點，對未實作的路徑顯示虛線提示；每段交接可展開「這段做什麼」與接口限制。狀態來自現有程式的**靜態檢查**，不是即時 API 健康度或回報接收狀態。

## 2. 雙向紀錄可見性

架構導覽頁可以獨立切換：
- 隱藏／顯示整個紀錄區
- 僅顯示**進站**或僅顯示**送出**
- 僅檢視**拒絕／退回**、**修正／重測**、**一般事件**

每筆紀錄展示：事件 ID、方向、事件類型、摘要、來源狀態及時間。展示頁預設是**虛構案例**；使用者在該頁手動新增的紀錄僅存在**本次頁面記憶體**，關閉或重新整理會消失，除非使用者下載候選包。不會讀取、輸出或修改加密記憶庫。

## 3. 可以套用的紀錄欄位

| 模板 | 必填與作用 |
|---|---|
| 資料進站 | 資料 ID、來源聲稱、取得時間、版本、來源證據、格式／權限結果、下一步 |
| 資料送出 | 任務 ID、預定收件人、人工操作時間、送達確認狀態、版本、分享權限、回報要求 |
| 拒絕紀錄 | 原候選 ID、拒絕原因、仍成立反證、影響範圍、退回對象、重測要求 |
| 修正紀錄 | 原 ID、版本、修改內容、新證據、未解決事項、重測方案、核准狀態 |
| 接口狀態 | 接口 ID、目前狀態、確認時間、資料流向、認證權限、錯誤與下一步 |

模板不會自動生成「事實」或「已驗證成功」結果。必填內容缺失時不能匯出。新的紀錄一律先變成**待審記憶候選**。

## 4. 路徑規劃與接口狀態

預設接口狀態（來自程式結構靜態檢查，非即時探測）：

| 接口 | 狀態 | 目前能做什麼 |
|---|---|---|
| Launcher | 人工交接 | 建立本機指令、複製、分享、匯出回報包 |
| 本機加密記憶 | 本機審核 | 候選審批、拒絕、版本更新、備份 |
| TCVL-04 | 展示模式 | 用虛構資料播放驗證流程、計算演練測試規則 |
| GPT①／GPT②／BOT③ API | 尚未接通 | 無法保證遠端自動送達或身份驗證 |
| 其他 AI／Webhook／企業資料 | 尚未接通 | 待未來具權限控管後端及資料契約 |

使用者選擇起點與終點，系統僅依*已定義的有向邊*規劃交接；含規劃邊的路徑標示未接通。按「交換起點／終點」會重新規劃，而不是假設送出與退回可以走完全相同的路。

快速架構頁可新增自訂節點、排列順序或移除。新的相鄰節點關係只是一個**待實作的規劃邊**，絕不會被標為實際可用的連線。

## 5. 完整架構如何進入加密記憶

1. 在 \`architecture-hub.html\` 選「**匯出完整主腦架構記憶包**」或只匯出目前快速架構。完整包涵蓋目前所有既有模組、在本頁新增的自訂模組、每個模組的用途／輸入／處理／輸出／狀態／驗證／交接／錯誤退回，以及路徑與接口狀態。
2. 下載符合現有 \`ai-boundary.memory-pack.v1\` 格式的 JSON，標示為**人工設計的待審候選**。不能自動宣稱 GPT① 已提供該內容。
3. 開啟 \`memory.html\`，解鎖本機加密庫，切到「提交候選」，按「匯入待審記憶候選包（含架構）」。
4. 進入候選審核頁，核對來源聲稱、版本與實際資料。可拒絕並記錄原因、修復後再提交，或人工核准。
5. 已核准架構在「版本記憶」保留；「主腦架構｜拒絕、修正與版本紀錄」可依全部、拒絕、修正、待審或已核准篩選，展開完整舊版、證據與修正理由。
6. 同名舊架構要變更時應由記憶管理頁手動比較，必要時用「修正答案／修正問題」追加版本或分支，不能從公開架構頁自動覆寫。

**限制：** 因為目前是加密的瀏覽器本機庫，公開架構頁不能直接讀寫私人庫。真正雙向同步、跨裝置共用或完整可信接口尚未建置。架構內容過長時，系統會拒絕直接生成候選包，提醒分拆，不能默默截斷資料。

## 6. 資料與測試責任

- 原始紀錄、拒絕紀錄、修正版可以並存，不應把異議刪除成一致答案。
- 審核／版本狀態和主張是否真實為兩件不同的事。人工核准不代表外部世界已驗證。
- 每次接口移動必須能區分「打算送達」、「已複製／分享」、「對方確實回報」、「通過驗收」。
- 回溯關係圖的「依賴」不等於已證實的因果；受影響記錄先列待重審。
- 正式記憶來源必須在解鎖區域查看；公開示範只可使用虛構或已授權脫敏資料。
- repo 是公開的，所有前端 JS 都可供外界檢視；展示影片隱藏程式碼並非技術上的程式碼保密。將來有專有規則應部署在受控的私人後端。
