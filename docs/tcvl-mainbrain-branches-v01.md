# 主腦｜分支式治理版圖 V0.1（獨立功能，不提前合併）

## 使用者確認的方向

主腦保持共同入口，但以下是獨立功能分支，不能因為同一網站可以點選，就宣稱程式、專案、資料庫、AI 或記憶已經實際整合：

| 主腦分支 | 目前用途 | 狀態及資料邊界 |
|---|---|---|
| 發射器 Launcher | 編排原始任務、人工發射指令 | 人工交接；不驗證遠端實際收件 |
| 三方 AI 中樞 | GPT①／GPT②／BOT③ 三條人工交接線 | 純交接封包，無自動 AI API 呼叫 |
| 專案治理 | 任務、停止、決策、對話、提醒、候選版圖 | 單頁記憶體＋明確 JSON 匯入匯出，沒有跨分支同步 |
| TCVL 架構 | 研究、反證、修正、欄位範本、路徑與設計狀態 | 設計與測試原型；不會直接讀取正式加密記憶 |
| TCVL-04 回溯 | 用虛構案例演示版本、反證、修正與影響 | 不是實際記憶事件，更不是三 AI 真實回覆 |
| 加密記憶庫 | 候選審批、拒絕、版本修正、加密備份 | 需要本機解鎖，不能自動跨裝置同步 |
| 世界模型研究 | 社會／企業／市場／政府等機制、條件與邊界的獨立研究 | 候選版塊；與 TCVL 連線尚未啟用 |
| 外部 AI／API | 規劃未來接口、授權及資料契約 | 尚未接通 |
| 3D 認知大腦與短影音 | 視覺與內容展示 | 既有頁面仍獨立，不能私下讀取／曝光加密記憶 |

## 分支規則（與使用者本批需求的關係）

1. **主腦僅顯示總覽：** `brain-branches.html` 展示功能狀態與清晰的輸入、輸出、下一步；未接線節點淡化顯示。
2. **共用的只有導航和非敏感顯示偏好：** `tcvl-platform-shell.js` 提供全平台狀態標籤、圖片樣式和「停止指定工作／拒絕提醒」入口。它不負責跨分支同步專案、工作或加密記憶。
3. **停止指定任務不停止對話：** 只有該任務的本機狀態切換成暫停；對話是獨立紀錄，繼續使用不受影響。不能聲稱停止已發送給遠端模型的任務。
4. **拒絕與阻塞應立即回報：** 在目前載入的專案或手動交接記錄中顯示原因、影響與下一步。別的分支未交接資料時，不應假裝有跨頁即時提醒。
5. **規劃路徑與啟用連線分開：** 先建立分支／依賴／交接邊及候選審核歷史；批准「設計規劃」不代表接口完成。
6. **私人資料不因為主腦總覽而外流：** 使用者明確匯出、確認內容、在另一分支匯入，再另行審核；不建立隱形共用資料庫。
7. **開發 Git 分支與功能分支是兩件事：** 本次維持 Draft PR #28，未合併到 `main`。使用者說的分支主要是產品架構中獨立的系統區塊；正式部署以後才決定要不要共用可驗證接口。

## 網頁調整

- `mainbrain.html` 的「專案工作台」及「三方中樞」**不再使用 iframe 內嵌**，改用獨立入口與說明，避免多個頁面實例同時運作造成狀態混淆。
- 新增 `brain-branches.html`：單一中心節點向下分支、可依領域篩選、顯示／隱藏規劃版塊、展開用途與資料邊界、列出有向的人工或規劃交接。
- `tcvl-platform-shell.js` 共用選單加入「獨立分支版圖」。
- `architecture-hub.html` 標明自身只是 TCVL 詳細架構分支，附返回主腦總覽的入口。
