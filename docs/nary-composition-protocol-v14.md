- 目的：容許 `A+B`, `A+B+C+D`, `X+E+F` 等 **N 個來源／結果的組合**，在有效條件下重用先前計算的 X；不重新讀取所有來源文字，不自動批准知識。
- 當前狀態：`ISOLATED_IN_MEMORY_CANDIDATE`；不寫 GitHub/main 生產入口、正式 memory、主腦 graph、journal、其他私人資料或遠端 ACK。Draft PR 是隔離程式提案，不是部署授權。

## 1. 先確定「＋」是操作子，不是模糊的混合

任意組合的最小一般式：

```
C = F_v([A@r1, B@r3, C@r2, D@r4], R)
D = G_w([C, E@r2, F@r1], R2)
```

- `F_v` 是 **操作種類、規則 ID、規則版本**，不能省略版本；`R` 是參照條件／目的、時間、量尺或領域。若缺少實際可信運算實作，組合只能標記為「候選」，不能偽稱合成出已驗證新事實。
- 不預先限定輸入屬於世界模型或記憶體，可是文件、數值、知識候選、比較結果、研究證據、工具結果或其他來源的 **唯讀投影**。
- 一次直接組合限制 2–32 個輸入以防資源濫用；可經樹狀層級將 40、80 等輸入組合，只要未超過深度、節點和展開葉節點上限。這是工程保護，不是概念上的 `A+B` 限制。

### 操作代數契約

| 操作類型 | 這版實際能力 | 順序敏感 | 結合／去重規則 | 真實語意限制 |
|---|---|---:|---|---|
| `collect` | 整理多個來源的 **引用集合** | 否 | 在相同規則/版本/參照條件下滿足集合律，排序去重、扁平化 | 不產生新事實；相同來源可有多段不同引用，不能直接當獨立研究 |
| `sum_integers` | 真正執行安全整數求和，回傳 `computed_value` | 否 | 相同規則/條件下聚合；重複輸入會重複加總 | 只適用安全整數；拒絕中間或結果溢位；不是語意真理 |
| `sequence` | 保留 A→B→C 的有序引用 | 是 | 不交換、不自動扁平化 | 事件順序本身不證明因果 |
| `compare` | 保留比較方向與比較條件 | 是 | 不交換 | A 比 B 大與 B 比 A 大不同 |
| `derive` | 登記可追溯的「規則版本 + 輸入」研究候選 | 是 | 不假設可交換、可結合 | **沒有**通用自然語言合成執行器，僅儲存規則身份與依賴引用 |

**特別注意**：`collect` 是「引用集合」的同一性；不是語言歸納的同一性。`sum_integers` 在 JS safe integer 邊界嚴格拒絕中間溢位，故超大正負混和運算可能因分組不同而一方拒絕；所有真正有效結果均需通過安全界線，不能宣稱任意浮點運算都完全符合結合律。

## 2. 最小資料與安全模型

### 來源節點

- `id`：本引擎的本地引用 ID；`revision`：來源提供的、不重複的版本標籤；`sourceId`：宣告的原始來源識別，供**宣告來源去重**，不是來源可信驗證。
- `payload`：僅允許有限深度、有限大小的 JSON 內容；內容指紋使用 SHA-256；並**不代表**已認證真來源。
- `capabilities[]`：**呼叫端已驗證**的存取許可名稱；隔離原型不具備真正身分登入或可信憑證服務。若不可信呼叫端自稱持有許可，本模組不能替代外部認證。

### 組合節點

- `id = 'cmp:' + sha256(canonical({operator, context, input_refs}))`；只處理受控長度、型別的引用及版本。**ID 非密碼、不等於安全令牌**。
- `input_refs`：直接輸入及內容指紋；`leaf_refs`：當操作具明確可扁平化條件時的引用展開，保留版本。
- `declared_source_id_count`：原始來源 ID 的去重數量，**不是**獨立研究數量。不同媒體轉貼同一證據，仍可能不獨立。
- `context_hash`：參照框架內容雜湊；`computed_value` 僅在可真實運算的安全整數求和時有值，否則 null。
- 固定 `authority='none'`、`evidence_certification='UNVERIFIED'`、`memory_approval='NOT_APPROVED'`、`real_ack='NOT_VERIFIED'`。

### 快取和安全

1. 相同來源版本、規則版本、參照條件與規範化輸入可命中同一個組合 ID，**不用再建立相同節點**。
2. 新來源修訂會把其下游組合標成 stale；舊 C 不能繼續作為當前有效引用，需再用新修訂重新組合。
3. 讀取 C 前，遞迴檢查所有直接及間接依賴的存取許可；使用者不能只持有 C 的 ID 就取走 A 的受限內容。
4. `revisionsSeen` 在本地程序內禁止已使用過的舊版本標籤被默默重新登記為最新；這不是完整外部版本權威或持久修訂日誌。
5. 不支持輸入任意 JS 邏輯或外部執行指令：`derive` 的規則只登記身份，不執行未審查程式。
6. 避免反向把 `context_reference`, `related_to`, `depends_on` 或 `causes` 混用；本引擎沒提供權威因果批准方法。

## 3. 可傳輸的 C 和節省條件

初始一次性傳輸可能要載入 A、B、C、D 的原始內容並驗證。接著 **雙方已具備相同來源目錄與可回讀組合 ID**，後續傳 `{ref:'cmp:...', content_hash:'...'}` 才可能少傳大量原始字元。若對端沒有相同版本/內容、授權目錄或拿不到依賴，單一 C 的 ID 只是無法解析的代碼，不能冒稱「成功傳遞資訊」。

需測量：原始 bytes、引用 bytes、快取命中率、建立和讀取延遲、P95、失效/重算次數、錯誤率、來源完整性、額外儲存/索引成本。不能只拿本地測試證明線上大幅提速。

## 4. 分層、失效與下一工程接口

```
Source A ─┐
Source B ─┼─ collect(A,B,C,D) ──> X ─┐
Source C ─┤                          ├─ derive(X,E,F) ──> Y (unverified)
Source D ─┘        Source E,F ────────┘
```

不直接灌入 `aiBrain.v1`；下一步用隔離薄型 adapter 將 V1.3 `candidate_only/HOLD` 研究包封裝成來源引用，不可讓 adapter 修改主腦資料、授權狀態或私人記憶。若 PR #122 變更，應固定依賴 SHA 重跑。

上層應可選擇 `collect`、`compare`、`sequence`、`derive`、`sum_integers` 等適用操作。下一版如需真正自然語言語意合成，必須新增**經審核且帶版本的外部轉換執行器**，有來源比對、反證及輸出核對；V1.4 不能宣稱已做到。

## 5. 工程驗證與失效矩陣

- N=2/3/4/6/40 階層、多次組合、相同輸入重用與不同操作代數。
- `collect` 順序不敏感、合法扁平化；`sequence/compare/derive` 不當作交換律或結合律。
- 版本、規則及參照變更時生成不同 ID；來源修訂使直接與間接下游失效。
- 拒絕未知算子、任意欄位注入、無效 JSON、循環 JSON、過量節點、過深組合、錯誤版本回退。
- 缺權限無法透過 C 洩漏 A；源 ID 同一性只能計算宣告來源數，不宣稱證據獨立。
- 真正 `sum_integers` 運算、重複加數、非整數、溢位、版本不匹配。
- 合成 payload 經 UTF-8 實測壓縮引用 bytes；**不是 WAN 速率、Token 節省或外部同步 E2E**。

## 8. 本版限制

此版本是 **瀏覽器相容 Web Crypto + in-memory Map** 的隔離研究原型。沒有持久化、遠端資料交換、HTTP 服務、任務調度、跨分頁交易鎖、正式權限驗證、分散式簽章、自然語言真值計算或自動正式記憶寫入。`sum_integers` 只用於經驗證的安全整數；`collect` 本質是引用，不是完整文意的合成。

**總結：支援任何領域的 N 輸入「可追溯組合與重用」，但每一種「＋」代表的操作需要明確的規則，並不得提升原始資料的權威。**
