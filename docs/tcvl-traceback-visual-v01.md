# TCVL-04｜回溯驗證視覺原型 V0.1

## 定位

本分支只新增 `traceback-visual.html`，不更動 `memory.js`、`memory.html`、`launcher.html`、`memory-workflow-core.js` 或正式記憶庫。頁面為**純虛構示範**，可獨立開啟，用於討論介面與錄製展示影片。

### 展示三種回溯
1. **歷史回溯**：保留原主張、反證及版本來源。
2. **錯誤／影響回溯**：區分「引用依賴」與「已證實因果」，標出需要重新審查的記憶與任務。
3. **修正回溯**：把舊版和待核准候選並排，保留未解決條件與後續重測。

## 互動
- 五個可跳轉階段、上一階段／下一階段／重播／自動播放。
- 可見的虛構示範標籤、原始／修正前後對照、複製示範摘要。
- 手機版響應式排版；影片展示可按自動播放錄螢幕。
- 沒有向外部接口傳輸、沒有讀寫 localStorage、沒有讀取私有記憶。

## 本版未完成
- 不讀取實際的加密記憶，沒有動態依賴圖或證據真偽驗證。
- 未實作模型對話、實際測試執行、AI 身分驗證、時間隔離回測。
- 尚未通過手機與桌面實機瀏覽器驗收。
- 待後續設計實際事件 ID／版本 ID／時間戳／依賴關係的**唯讀、授權式**資料導入，需避免外洩私人資料。

## 手動驗收
- [ ] 手機開啟，五階段可點選、文字不溢出
- [ ] 下一階段／上一階段邊界停用正確
- [ ] 自動播放、暫停、重播正常
- [ ] 影響掃描階段顯示受影響節點而非直接宣稱因果
- [ ] 複製摘要可用／拒絕剪貼簿權限時有錯誤提示
- [ ] 無對外網路請求、無私人資料存取
- [ ] 返回記憶管理的超連結正確

本原型不得作為「已完成三方 AI 即時驗證」的商業證明。


## 2026-10-15｜測試邏輯 V0.1（新增，未合併）

新增 \`tcvl-traceback-core.js\` 和 \`tests/tcvl-traceback-core.test.cjs\`，視覺原型可載入核心，在**虛構示範資料**上執行三方處置測試及依賴影響追查。首輪獨立 Node.js 測試結果：**19 項通過，0 項失敗**。後續為修正『晚到資料的歷史穿越』增加 2 項測試，目前共有 **21 個測試案例**；新增修改尚未重新執行完整測試，所以不能聲稱 21 項已通過。此數字不代表正式產品、三個 AI 或瀏覽器端已驗收。

### 純函式規則與邊界
- \`validateHistory\`：驗證 schema、唯一 ID、時間與依賴關聯；不證明來源真實。
- \`replayAt\`：僅顯示在截止時間前**已發生且已被系統記錄**的事件，且資料本身具有不晚於截止時間的 \`recordedAt\`，防止晚到資料混入歷史重建。
- \`impactOf\`：只沿 \`depends_on\` 連線反向追蹤，將可能受影響記錄標為「待重審／暫停」；不自動宣布結論錯誤，也不將 \`related_to\` 視為依賴。
- \`tripleCheck\`：GPT① 方向、GPT② 證據、BOT③ 條件變化，各必須帶結果及理由。可區分通過、失敗、未知、測試無效；**即使全部通過也不能自動核准**。
- \`reviewRejectedReuse\`：舊版否決 ID、原因、新證據、剩餘反證、重測範圍、責任歸因。僅做到欄位及 ID 可追溯，尚未進行證據真偽或內容一致性查核。
- \`compareRetests\`：只有研究案例、測試規則及資料截止時間一致才能比較通過／失敗；有未知或無效結果時不宣稱改善。此為單一測試比較，不代表普遍能力改善。
- \`validateMovement\`：檢查移動事件是否有進出來源、目的地、版本、校驗碼、時間、結果；**尚未真的計算雜湊或驗證資料傳輸**。

### 已執行的 19 個單元測試分類
- 歷史格式、重複 ID、關聯不存在檢查：3 項（新增：缺少資料接收時間拒絕 1 項）
- 指定時間點回溯、避免未來資訊外洩、不可變資料：3 項（新增：晚到資料不可回溯混入 1 項）
- 依賴反向掃描、非依賴關係排除、暫停狀態、時間隔離：4 項
- 三方方向／證據／條件測試、退回與無效處理：3 項
- 被拒絕資料重新使用及新證據缺口：2 項
- 同條件修正前後比較與不可比性：3 項
- 匯入／匯出事件欄位檢查：1 項

## 架構導覽及快速架構｜2026-10-15 新增

### 為什麼設計
**面向使用者：功能與交接先於程式碼。** 新增獨立介面 \`architecture-hub.html\` 作為 Launcher Hub 導覽頁，不要求使用者閱讀原始碼。模組點選後展示：
1. 本模組要解決什麼問題、目前完成度。
2. 接收哪些資料（輸入）。
3. 做了哪些處理及如何判斷（作用）。
4. 交付哪些回報（輸出）。
5. 將結果送去哪一個模組（下游）。
6. 若出錯要退回哪裡、驗證缺口在哪裡（反向追溯）。

### 快速架構
- 內建四種範本：一般研究驗證、被否決資料重測、外部接口資料進出、歷史回溯影響查核。
- 可選擇加入現有模組，也能新建**自訂模組**（名稱、輸入、處理、輸出、反向退回）。
- 架構步驟可排序、移除、還原範本；可複製人類可讀說明或匯出 JSON 規格。
- 產出的僅是設計草稿，資料不寫入正式記憶，也不創建 AI 任務或伺服器端接口。
- 若缺少資料治理或記憶節點，預覽顯示提醒，不把不完整的流程宣稱可正式部署。

### 同平台導覽
- \`launcher.html\` 增加「架構導覽與快速設計」及「回溯驗證」入口。
- \`architecture-hub.html\` 點任一模組可在右側讀取六類資訊；「用這個節點回溯」會導航到 \`traceback-visual.html#<module>\`。
- \`traceback-visual.html\` 能依模組參數選取對應展示階段；三方測試各有獨立的狀態與原因欄位，會說明應退回哪個角色。
- 所有功能沿用公開展示與本機手動交接的邊界，不暗示已連到遠端 AI。
