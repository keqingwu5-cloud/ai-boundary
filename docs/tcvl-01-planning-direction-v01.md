# 文件 ①｜主腦未來方向與專案版圖 V0.1

**文件定位：產品與研究方向。** 本文件回答「主腦為什麼發展、先做什麼、預計接到哪裡」。它**不負責**詳細執行規章或拒絕裁定；這些分別交給文件 ② 與 ③。

- 狀態：**候選規劃，待使用者審查**。
- 適用對象：Launcher Hub、TCVL 模組、治理工作室、記憶管理、專案對話與未來擴充接口。
- 修改原則：新規劃建立提案版次與理由，不直接更改已核准正式架構。
- 相關文件：`tcvl-02-memory-governance-rules-v01.md`、`tcvl-03-rejection-correction-observer-v01.md`。

## 1. 發展目的

主腦不是增加最多 AI 或收集最多資料，而是讓人類**理解系統如何工作、持續保有可追溯的記憶、減少重複失敗**。資料可累積不代表結論會自然變好，因此每次進展要保留「過去版本、支持及反對證據、修正理由、適用條件、下一次驗證」。

平台採取四個可辨識的視角：

| 視角 | 觀察內容 | 成功定義 |
|---|---|---|
| 專案視角 | 目的、任務、階段、對話、計畫觀察員 | 每個階段可以對回核准的原始計畫 |
| 架構視角 | 版塊、節點、接口、資料進出、依賴路徑 | 一眼看懂每個節點做什麼、交給誰 |
| 記憶視角 | 原始、候選、核准、否決、修正及版本 | 不刪掉不利證據，能還原當時已知資訊 |
| 驗證視角 | 前、中、後對齊；反證、重測、回溯 | 能分辨改善、退步、未知及測試無效 |

## 2. 統一入口設計

**Launcher Hub 作為共用入口**：開啟專案、共同對話、架構圖、記憶、回溯、拒絕提醒、執行狀態與設定。入口共用不是把全部資料寫進同一個巨大檔案；底層功能應分模組、以共同 ID/契約關聯。

建議操作：`選擇專案 → 查看核准計畫 → 觀察員前置對齊 → 指派 GPT①/GPT②/BOT③ → 中途比對 → 回報／拒絕／修正 → 人工驗收 → 記憶候選`。

**新對話需掛在專案之下**，紀錄 `project_id`、`conversation_id`、`plan_version` 與 `context_scope`。開新聊天窗不等於清空任務：要顯示目標、上一輪決策、未完成待辦與本輪採用的記憶版次；但未經授權不能任意跨專案讀取私人記憶。

## 3. 「新版圖」與正式版圖分離

| 位置 | 可做什麼 | 限制 |
|---|---|---|
| 新構想候選區 | 建新節點、分支、接口、路徑；自由排列與附註 | 不代表已有權限、資料或真實連線 |
| 待審架構 | 補用途、資料契約、風險、驗證方式、回退方案 | 必須保留原方案作對照 |
| 已核准設計 | 有核准人、設計版次、依賴與責任範圍 | 仍須個別實作與測試，非自動「已上線」 |
| 已實作功能 | 可展示可追蹤的實作與單元測試 | 不等於已完成整合驗收 |
| 已正式驗收功能 | 具完整系統測試、負責人、回退及上線證明 | 遇到新錯誤需回復「待重審」 |

**未啟用版塊虛化展示**：對「規劃中、等待接口、待核准、暫停」等不同狀態提供清晰文字，不只靠透明度區分；可展開「尚缺什麼、下一步、預計接口」。不能讓未完成的按鈕看起來能執行。

## 4. 全平台共用能力（以需求候選登記）

1. **共用狀態選項**：工作、模組、接口、知識各自定義狀態，不混用「節點測試通過」「任務完成」「已接線」。
2. **工作停止鍵**：對指定 `task_id` 要求暫停或中止，保留當下進度與理由；聊天仍可正常進行。尚未接線的外部 AI 不能宣稱遠端工作已真正停止；需要執行端回執。
3. **拒絕即時提示**：在實際拒絕事件發生時顯示原因、影響、修復條件與下一步；避免使用者問過才得知。
4. **共用圖片設定入口**：預留顯示方式、隱私遮蔽、示意／真實來源標記、錄影展示模式。具體參數後續再定義，未獲同意不公開原始圖像。
5. **路徑擴充**：節點可新增分支、依賴和外部接口，保留既有 ID 與版本；新增關係先標記「候選」，不暗示已具備通訊能力。
6. **預審入口**：使用者在任務啟動前可檢視目標、參與者、執行權限、反例測試和停止條件。
7. **狀態與設定總覽**：一次查看專案進度、阻塞、未核准候選、修正待驗與尚未啟動板塊，而不是把每則提醒塞進聊天。

## 5. 開發順序與界線

**第 A 階段：先分離文件與共通資料定義**。確立文件 ② 的不可變治理原則，以及文件 ③ 的觀察員與拒絕修正流程；此步可以只做規格，不碰正式記憶。

**第 B 階段：做專案對齊的最低可用流程**。以虛構案例示範「前置計畫、期間偏離、後置驗收」的三道門檻；畫面顯示與規則判斷都需要可追溯的相同 `project_id`／`plan_version`。

**第 C 階段：整批加入介面候選**。共用狀態選項、拒絕通知、停止、圖片設定、路徑圖、新版圖、新對話，先以功能開關或虛化模組呈現；不為每個候選另開不必要的長測試專案。

**第 D 階段：一次整合驗收**。對共通 ID、狀態遷移、停止鍵、記憶保護、拒絕修正與路徑規劃集中執行測試；必要的安全保護與格式檢查仍應在實作當下做，不能完全跳過。

## 6. 驗收成果與商業呈現

對使用者展示的是**專案版圖 + 當前狀態 + 反向修正路徑 + 有證據的歷史**。影片可隱藏實作細節，清楚標示「模擬」或「真實驗證」。衡量工作成果不以程式行數，而以重複失敗減少、可回溯範圍、流程合規、無效測試比例、人工時間與實際成本衡量。

### 尚未做的承諾

本規劃**不代表**三方 AI API 已接通、共享雲端記憶已部署、各接口已監測、停止可控制外部系統，或已通過正式安全審查。規劃與已實作狀態必須分欄展示。
