# 主腦方向交接｜2026-10-21

**資料性質：** 使用者構想及待驗證推論；公開研究記錄。不是已核准私人加密記憶，不代表客觀事實已驗證。

## 1. 主腦的目的：組織產生能力

- 工作流是初期必要條件，而非最終競爭點；核心是把想法快速轉化成可測試、可重用的能力。
- 主腦作為大量 AI 工作者的媒介，按任務調度模型、工具、角色、驗證、權限與資源；單純取 BOT 名稱及提示詞不構成獨立能力。
- 共同記憶的首要目的，是保存方向、理由、假設、取捨、決策及修正，跨模型換代維持脈絡；候選研究內容不自動升為權威記憶。
- 優先解決資金與運作資源，再發展可持續規劃／執行／驗證／迭代的 AI 組織；所謂「永動機」指工作循環，不是無成本無停止。
- 組織循環：**方向→拆分問題→調度能力→執行→反證→儲存→修正→繼續規劃**。

### 量化衡量

想法到可用原型時間、首次獨立驗證時間、每份有效結果的成本、返工率、模型替換的相容率、任務完成率與安全停止率。比較單一 AI／多提示詞角色／有工具與權限隔離的代理系統，不能假設多 AI 必然較強。

## 2. 安全先思考失敗路徑

資料污染、記憶污染、身分偽造、越權、跨代理共用錯誤證據與成本失控，先在**授權隔離環境**進行攻擊情境測試，再以形式條件、來源追溯、程式授權、回滾與停機保護檢驗。數學是驗證能力，不一定需要固定「數學家」BOT。多 AI 共識不等於獨立證據。

## 3. 動態視覺與影片研究

轉譯：**語意概念→物件→位置→關係→狀態→動作→鏡頭→連續影格或互動 3D**。

| 概念 | 畫面映射 | 必須驗證 |
| --- | --- | --- |
| 節點擴張 | 中心脈衝、生成子節點、建立連線 | 是否看出新增能力／資訊 |
| 路徑流動 | 光點沿有方向的邊移動 | 是否看出方向與起訖 |
| 風險擴散 | 警戒狀態沿相依關係傳播 | 示意不能冒充實際因果 |
| 任務傳遞 | 任務載體 A→B；收件節點狀態更新 | 是否確有交接紀錄 |
| 層級展開 | 折疊、父子節點空間展開 | 是否理解階層關係 |
| 點擊聚焦 | 鏡頭移動、關聯高亮、無關節點降噪 | 是否提升理解 |

影片模型常在壓縮時空表示中產生影格再編碼；Three.js／Blender 的真 3D 是以明確物件、時間規則及鏡頭渲染。比較精準度、時序一致性、可互動性、4K 輸出成本，不假設所有影片模型內部架構相同。這裡只是研究項目，未產生實際影片。

## 4. 1–2 年硬體市場假設（重點）

**提出的 H1（非已證實）：** 2026-10～2028-10，個人化 AI 軟體與工作負載大量湧現，使既有一體化手機／終端在算力、RAM、功耗、散熱、維修或升級成本上出現錯配。可能的產品機會是可維修模組化硬體、跨裝置標準、可選功能組件與輕量終端＋雲端 AI。

**候選因果鏈：** 軟體個人化↑→需求多樣性↑→本地硬體需求分化↑→整機購買／換機總成本更顯著→模組化／外部算力／新型終端需求可能增加。

**同時保留反證假設：**

- H2：晶片、電池與端側 AI 加速快速提升，使硬體足以跟上需求。
- H3：大量個人化軟體由雲端處理，本地硬體需求並未明顯上升。
- H4：模組化因接點、散熱、防水、相容與規模成本，總價反而較高。

**接下來應蒐集：** 端側應用需求、RAM／儲存／功耗和電池限制、裝置售價與換機週期、維修頻率、模組採用率、雲端訂閱總成本、標準化與零件可得性。選定市場、時間點及基準後才能判斷是否出現結構性錯配，不能因為手機昂貴就直接認定硬體市場將崩潰。

### 6.2 同一份資料、四種可切換的觀看方式

| 視圖 | 在現有基礎上增加 | 不得誤導的事 |
| --- | --- | --- |
| **3D 探索** | 保留 Three.js 腦區、空間節點、現有焦點與概念光弧；以開關疊加任務／來源的提示 | 節點在畫面上的幾何距離不代表實際因果、地理或工作成本 |
| **2D 樹狀總覽** | 用現有 parentBrainId／parentId 建立單向、可折疊的 tidy-tree；節點選取與 3D 深連結互通 | 跨領域連結不得偽裝為父子關係；不能由推導的樹位置覆寫 3D 坐標 |

### 6.3 平面排版：先手機可讀，再桌面擴展

1. **頂列共用狀態**：目前視圖、全局／子腦麵包屑、搜尋、資料最新觀測時間，Release Gate 顯示 \`HOLD\` 等來源狀態；不只用顏色表達。
2. **主區域**：2D 樹／關係網／現有 3D 擇一放大，能聚焦、縮放、收起分支；節點密集時先按層級或來源分組，避免滿版線條。
3. **節點詳情抽屜**：接在原 \`#panel\` 的資訊模式後，分段列「它是什麼 → 依據 → 不確定性 → 反證 → 相關任務 → 可用動作」；不擠滿所有指標。
4. **AI 協作視圖**：同任務下可查看 GPT①／GPT②／BOT③ **原始回件／證據引用**與差異，並以資料狀態顯示 \`DISPATCHED\`、\`MANUAL_BRIDGE\`、\`RECIPIENT_ORIGIN_EVIDENCE\`、\`ACK_UNVERIFIED\`、\`REVIEWED\`，**不是模擬三個 AI 已在群組即時互聊**。
5. **手機／iPad**：沿用現有 \`#panel\` 手機底部抽屜模式，2D 圖使用觸控縮放、鍵盤替代操作；減少大面積同時開啟面板。未啟用功能顯示禁用原因，不偽裝成功。

### 6.4 任務證據範例（僅示意資料）

- 同一個審核項目顯示兩包：\`#138 @ a8f255b443cf0ec120be6dad39758f7d3a4e02e3\`（父層完整實作）和 \`#139 @ 39338c429fff6ed8b81a923d63b6c064e6f229cb\`（修補差異）；**兩包各自的驗收範圍及結果不得合併顯示為「全過」**。
- 對 GPT②／BOT③ 只存在「已發布交接」時，畫面顯示 \`DISPATCHED / ACK_UNVERIFIED\`；人工轉貼顯示 \`MANUAL_BRIDGE\`；接收方的可查原始對話只至多顯示 \`RECIPIENT_ORIGIN_EVIDENCE\`。無受認證接收端時，\`ACK_VERIFIED\` 保持不可用，而非自動宣布審查 FAIL。
- \`code_review_status\`（工程審核）、\`receipt_origin_status\`（回執來源）、\`permission_gate\`（授權）是三個獨立欄位。任何視圖不應從其中一個 PASS 自動推導另外兩個 PASS。

### 6.5 與「世界如棋局」跨尺度研究連接

先保留六個研究參數：\`spatial_scale\`、\`temporal_window\`、\`system_level\`、\`resolution\`、\`reference_frame\`、\`distance_metric\`。示例：地圖距離、物流時間、圖譜步數及資訊傳遞延遲是不同量。介面顯示所用單位、來源與轉換前提；不同尺度的解釋可以並存，但**相同條件下相互衝突的可檢驗主張仍須反證**。此處是視圖規格，**不是已驗證的跨尺度因果模型**。
