# 自我差異性判斷｜提出者自審
對照同一事件前後差異（7）及現行版本、既有驗證（10），分清重跑與更正，標出證據能支持的原因。
發現問題即轉修正；缺關鍵原件就標待證，帶具體缺口求助。準備正式送審時，須先修正並複核至範圍內無已知未解問題（14）。

## 動態自審（非固定清單）
已發現的缺口只是當前範例，**不是固定兩項、固定輪次、固定題數或永久不變的審查範圍**。依受審事件、版本差異、新反證與實際風險，按需新增、合併、縮減或撤回檢查；保留每次調整的原因、來源、所影響的主張與原始結果。
- 已有同版、同前提的充分證據 → 重用並作範圍裁決；不能因「還可以多測」而重跑。
- 出現新版本／新失效模式／證據互相矛盾 → 先核對差異，只補能改變結論的最小檢查；不把舊版 PASS 冒充新版驗收。
- 原件或環境缺失 → 明確標 `待證 / BLOCKED / NOT_RUN`，列具體缺口；不以無限自審取代獨立審查。
- 同版可支援的主張已裁決，且沒有剩餘的已知可行、能改變結果的檢查 → 停止自審；其餘風險交給真正未參與修補的審查者，保留使用者的正式核准 Gate。
- 自審的 `LOCAL_FORMAT_CHECK_PASS`、CI PASS、來源查核與 `INDEPENDENT_ACCEPTANCE` 分開記錄，任何一項不得自動升格為可信遠端 ACK。

## 證據收斂：先找能減少問題的關鍵證據
這裡的「減少」是**減少未解問題與重複驗證**，不是刪除原件、降低證據數量或隱藏反證。面對數個疑問，先問「哪一份可核對的證據，可以同時區分最多重要的互斥解釋？」；不是先增加測試題數。

每個候選證據建立最小對照：`evidence_id/source_ref/version | 能直接回答的 problem_id | 必須成立的條件 | 不能證明的邊界 | 已有/缺少 | 取得成本與風險 | 原結論→新結論 | 下一個 Gate`。
- **既有證據優先**：先找同版原始程式、測試命令、log、實際連線、收據；同一 CI 即使回答多題，也只是一個來源，不假裝有多個獨立審查者。
- **選最有辨識力的新增證據**：能同時排除多個高風險假說、成本較低且不擴權的優先；若兩種假說都能解釋同一結果，就不能以該證據結案。
- **逐題標記收斂而非一鍵全 PASS**：一份證據可讓部分問題 `RESOLVED`、部分 `SCOPE_LIMITED`、其他仍 `BLOCKED/NOT_RUN`；不延伸到未測版本、獨立身分、遠端 ACK 或正式環境。
- **保留原證據與剩餘問題**：每次問題減少都必須留下「由哪筆證據使哪個問題關閉，哪些仍未知」的回鏈；新反例可重新打開問題。
- **動態停止**：證據已足以判斷、剩餘檢查不會改變決策時停止；若高風險且證據不足，保留 Gate，不強迫湊出 PASS。

第一大腦候選實例（不可互相冒充）：同版 #101 CI 可一次檢查 HTTP 識別與交接合成回歸，但不是真 PG/受信 ACK；#97 真 PG 8/8 可支持舊版已涵蓋的路徑，但不能覆蓋雙 client 競態；獨立目的端的原文讀取→執行收據→簽章 ACK→來源端讀回，可一次減少多項交接疑慮，但只有真正分段證據俱全才能判為可信閉環。
