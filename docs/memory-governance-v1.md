# 主腦共同記憶治理 V1｜本機加密可用版

入口：同網站 `memory.html`，從 `mainbrain.html`、`index.html`、`launcher.html` 進入。

## 定位與範圍

本版把「記憶提案 → 人工審核 → 有歷史的新版本／分支 → 拒絕原因與修復 → 每日差異 → 手動備份與交接」做成可用操作介面，而不是只有規劃圖。

**實際儲存位置**：目前裝置瀏覽器的 `localStorage['aiBoundary.privateMemory.v1']`。儲存的資料以 Web Crypto（PBKDF2-SHA-256，260,000 次、每個庫 16 bytes salt，AES-GCM-256、每次存檔不同 IV）整庫加密；密碼僅在解鎖操作中使用，不以明文保存在 localStorage。需 HTTPS 和支援 Web Crypto 的瀏覽器。

**不是已完成的雲端共用記憶**：不同裝置沒有自動同步；GPT①、GPT②、BOT③ 並未獲得自動登入／執行／回報接口。加密記憶庫不可直接讓 AI 讀取，只有使用者主動匯出單一候選或 AI 回報草稿。其他同源站點程式仍可能造成威脅，安全性不等於經第三方稽核；此為早期個人本機模式，建議避免儲存金鑰、帳號密碼和高敏感資料。

## 最小可用操作（手機）

1. 開啟 `memory.html`，設定至少 12 字元密碼，再確認密碼，建立本機加密庫。重新整理後需重新解鎖。
2. 到「提交候選」選擇事件類型，填寫「原問題、目的、候選內容、證據／不確定性、修改理由、提出者」。若為修正答案／修正問題，先選擇關聯的既有記憶。
3. 先按「提交候選」，資料進入待審清單，不會直接寫入權威版本。
4. 到「候選審核」選「核准」或「拒絕並寫理由」；拒絕後可重新提案，舊拒絕紀錄不刪除。
5. 修正答案沿用原問題與目的並追加 `versions[]`；修正問題會在原記憶旁建立 `question_revision` 新分支；提出新問題與踩坑另建主題。拒絕後的修復版若核准，原拒絕項目保留並標示已修復。
6. 「版本記憶」可展開歷史版本，「差異與備份」可按當日日期查看事件、下載加密 JSON。
7. 將其他 AI 回報輸入發射器並匯出回報 JSON 後，在「提交候選」按「匯入發射器 AI 回報 JSON」。只會填表，不會自動吸收；請人工調整分類、證據與目的後再提交。
8. 換裝置可下載加密記憶庫 JSON，傳至自己的新裝置，在未解鎖畫面按「從加密備份復原」，以原密碼解鎖；此操作將**取代**目標裝置既有本機記憶庫，務必先備份。

## 嚴格檢查

- 候選寫入不是核准。
- 修正答案不得修改既有問題與目的；問題改義必須開新分支。
- 修改與審核保留原版、提出者自填來源、理由、證據層級及時間。
- 拒絕需填理由。相同且未修訂的被拒提案不能直接重新提交。
- 完全相同待審內容不可重複提交。
- 若是 AI 提出的既有問題修訂，使用者需人工確認原問題對齊／修正是否適當；**介面無法驗證遠端 AI 的真實身分或回覆**。
- 表單／匯入回報使用純文字呈現，不執行其中的程式碼或外部指令。
- 加密備份可還原（需原密碼），但忘記密碼無法救回。
- 本機權威僅指使用者批准的版本，**不是公理或三 AI 共識**。

## 驗收清單（人工實機）

- [ ] 首次建立、重新整理後解鎖、錯密碼提示
- [ ] 新提案→核准→主題出現；修正答案→版本從 1 變 2，舊版仍在
- [ ] 修正問題→新分支並保留原問題
- [ ] 拒絕→填原因→修訂提案→核准→原拒絕轉已結案但歷史仍在
- [ ] 同內容待審重複提交被阻擋
- [ ] 當日事件與差異統計更新
- [ ] 下載加密備份→重新匯入→能以原密碼解鎖
- [ ] 手動匯入發射器回報 JSON→只填草稿，不自動核准
- [ ] 檢查網路請求：記憶管理頁不向外發送個人資料

## 尚需建置的正式主腦

- 安全登入＋伺服器端授權代理＋私人資料庫與備份。
- 遠端可核驗的三 AI 身分、原提出者語意對齊、加密傳輸與存取權限。
- 中央合併／衝突仲裁、版本鎖定、重放防護、候選增量審核與去重。
- AI 實際的任務領取／完成回報及費用預算、超時處置。
- 多裝置差異報告與私人推播。
- 正式安全測試與資料遷移。

另有後端概念與程式骨架待審 PR #19： https://github.com/keqingwu5-cloud/ai-boundary/pull/19 。本版**不部署該後端**，不宣稱任何遠端 AI 已自動連線。

## V1.1 記憶完整性修正（BOT③ 回饋後）

已實作，尚須實機驗收：

- 對**待審／被拒／已核准**的候選做更廣的重複檢查：核心指紋忽略常見標點與空白，不依賴證據層級或修正理由來判斷是否同一主張；若有同問題但不同內容，會詢問使用者是否真的要開新問題。這不是語意向量比對，相似的不同措辭仍可能被漏掉，不能代替人工審核。
- 被拒內容不能改由「全新提案」無痕重送。應點「修正後重新提交」建立 `repairOf` 關聯；原版保留，補上新證據仍可重新審核。
- 本機加密庫增加 `vaultId` 與單調遞增的 `revision`，顯示目前版本。原 V1 本機庫在解鎖後會補上這些欄位並重新加密，既有候選及記憶內容不主動修改。
- 跨分頁寫入前比對上一次解鎖／儲存的密文版本，發現其他分頁改過會停止寫入並提示。這是降低競態風險的防護，不是跨裝置的原子交易保證。
- **還原已有的本機庫**時，必須先解鎖原庫，下載目前加密備份，再二次確認；匯入較舊版或不同 vaultId 會顯示風險。使用者明確確認後仍可覆蓋，因為「手動強制復原」和「靜默回滾」不同；目前不提供跨庫自動合併。
- 容量達上限的提示已澄清：下載備份**不會釋放空間**。封存、刪除、隱私遮蔽仍屬下一階段，請不要在此版本存放大量或高度敏感資料。

**仍未修好：** 私人記憶與公開 GitHub Pages 同源的安全風險、AI 遠端身份認證、原提出者語意對齊證據、語意近似去重、封存／刪除、恢復碼、跨裝置合併／雲端同步、私人後端的交易一致性。這些不得以「已完成」呈現。
