# 安全獨立記憶體 V1｜隔離、回滾與完整使用驗收候選（不授權部署）
日期：2026-10-23（Asia/Taipei）｜project AI-BOUNDARY-TCVL｜範圍 PR #27、#58、#59

本文件為使用者「我們做下一階段」的**候選實作與發布前檢查**。不得將 GitHub CI/候選程式的成功理解成正式上線、獨立 AI ACK 或跨平台同步。PR #59 仍基於 PR #58；PR #27 的部分深層驗證已在 #59 候選程式中引用／改良，不能當作 #27 已合併。

## 已確認的 P0 隔離風險
當前公開展示頁 `memory.html` 與 `launcher.html`、主腦頁同屬 GitHub Pages 網站來源；`localStorage['aiBoundary.privateMemory.v1']` 依**來源（scheme + host + port）**隔離，不依 HTML 路徑隔離。即使密文無法直接解密，同來源腳本仍可讀取、覆寫、刪除密文，並可能接觸 Launcher 草稿。僅在記憶頁設定 CSP 不能阻止**另一個同來源頁面**操作該 storage key。本批 Chromium E2E 專門設計了安全觀察用例，若確認其他同源頁可讀取合成密文，這是**發布阻塞 finding**，絕對不是安全已通過。

**正式發布前的建議方案（尚未授權配置）：**
1. 選擇獨立私人記憶 origin（新 host 或獨立子網域；僅新增路徑不夠），並保持 `memory.html`、對應本機 JS、CSP、無第三方 script/fonts/CDN 及 `connect-src 'none'` 的獨立介面；檢查 service worker、Cookie、origin 授權與 cache。
2. 不讓公用主腦和 Launcher 取得記憶庫金鑰、密文或直接讀取權；它們之間只允許使用者明確執行的最小必要資料交接。新來源須檢查無不必要資料出站；不要透過公開 GitHub Issue、query string、URL hash 傳送敏感資訊。
3. **跨 origin 遷移沒有 localStorage 自動轉移**：舊來源保持原狀，由使用者先匯出加密備份，驗證可讀與版本，經明確核准後再在新來源匯入隔離副本、解鎖、比對、重新打開；切換完成前不能刪除舊庫。失敗時退回舊介面只讀，不自動嘗試可損歷史的覆寫。
4. 未設定新 origin、完成實際安全反證與平台核准前，現有公開版本**只能標記早期本機 prototype**，不適合高敏感或正式多人權威記憶。

## 兩道互不混淆的回滾
- **程式回滾**：鎖定已驗證的發布 commit、先暫停受影響的寫入（不是鎖死所有唯讀研究），回退靜態程式；若新版已變更資料結構，舊程式不得盲寫新庫，須提供只讀查看或受控的向後相容遷移。每次發布先保存對照的來源、版本、合成測試記錄和可撤回檔案集合。
- **資料回滾**：任何覆寫前先下載並確認**當前**加密備份可解鎖，之後在隔離副本測試目標備份、比較 `vaultId/revision`、候選、版本內容、稽核、方向門檻。舊 backup、不同 vault、相同版本號不同內容都需要風險提示。資料恢復仍需使用者確定，不能由程式回滾暗自替代；不能聲稱 `localStorage` 有跨裝置 CAS/雲端強一致。
- **回滾驗收**：模擬被拒絕的損壞檔案、錯密碼、容量故障、遷移失敗、過時其他分頁寫入、舊庫重播；錯誤時不丟當前加密庫、不丟原審核紀錄。真實資料不得作為故障注入測試治具。

## 完整使用證據分層
| 狀態 | 說明與最低證據 |
|---|---|
| G0 前置 | 固定 SHA、來源授權、PR 相依關係、儲存 origin、合成測試專用 profile、執行者與 rollback 方案 |
| G1 單元／隔離 | 基礎版本/門檻獨立、候選與拒絕、安全備份、裂變預演與風險負測，原始 TAP／CI |
| G1 真實瀏覽器 | 從真實 `memory.html` 建庫→解鎖→修改方向與門檻→候選預演→人工核准/拒絕→下載加密備份→插入損壞備份拒絕→手動還原已驗證舊備份→重載解鎖，使用合成資料；含 Console/page error 與出站檢查 |
| G1 隔離 | 在新 origin 實測公用頁**讀不到**私人密文，CSP/請求、敏感資料傳輸負測；不實際設置新 origin 就保持 BLOCKED |
| G1 回滾 | 靜態程式退版與資料恢復獨立測試，與版本格式相容性；跨分頁競態另做 |
| G2 審查 | GPT① 或授權獨立審查者檢查固定 diff、測試證據/負測與未完成，使用者再批准合併和部署；不把工具寫入同一 GitHub 帳號當成獨立身份 ACK |

## 這一階段的範圍限制
- 允許：僅 PR #59 已授權草稿分支的合成瀏覽器測試、必要小修補、唯讀威脅分析、文件、候選 CI。
- 不允許：更改正式 `main`、合併、公開或私有部署、佈署新 host、改 production DB/RLS、給 Launcher 私人記憶讀權、匯出私人密文或啟用 AI 自動核准。
- 不能將「GitHub CI success」當作新 origin 的隔離成功、真實跨 AI 接收，或已可以存放高敏感資訊；安全找出的失敗仍應保留而非為綠燈刪測試。

## 建議 go/no-go
1. 私人獨立 origin 是否真實可用並經雙向隔離負測？否 → **不正式部署**。
2. 真實瀏覽器功能閉環、備份安全還原與手動候選治理是否都通過？否 → 不合併／不宣布完整可用。
3. 使用者是否確認風險、回滾方案與範圍並**分別批准合併及正式部署**？否 → 保持 Draft。
4. 是否仍有身份/ACK/雲端共用資料庫尚未接通？是 → 僅可稱本機獨立 V1 候選，不得宣稱跨 AI 完整自動記憶。
