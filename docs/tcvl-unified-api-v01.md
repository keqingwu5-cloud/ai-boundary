# 主腦統一 API 與雙向接口訂製｜V0.1 設計／開發草稿

> **重要：目前沒有部署外部 AI 自動傳輸，也未修改 Supabase 正式資料庫。** 本規格是統一 API 骨架、雙向資料契約及可視化訂製頁。端到端測試、正式部署與金鑰託管仍待處理。

## 一眼看懂：介面與資料路徑

```text
使用者／專案對話
        │
        ▼
Launcher Hub → 統一 Brain API（身份、權限、任務、狀態、雙向事件）
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
        Outbound 送出            Inbound 收件
       權限與欄位檢查            回執及來源檢查
              │                     ▲
              ▼                     │
      外部 AI／工具／服務  ───────────┘
              │
              ▼
       TCVL 反證與資料治理
              │
              ▼
     待審候選 → 人工核准 → 記憶／回溯
```

上述資料路徑是**預定系統設計**；不是已經接通 GPT／Grok 或第三方工具的實際結果。

## 1. 接口無限擴充的原則

- **主腦 API 是唯一業務入口**：管理專案、對話、工作、停工請求、拒絕提醒、接口註冊與稽核事件。
- **每個服務是獨立連接器**：其提供者、能力和進站／送出規格由 manifest 描述，無須為每個新服務重建整個平台。
- **一個接口，兩個獨立方向**：進站及送出可以使用不同格式、允許不同事件、不同欄位對應與錯誤處置。
- **新接口先以候選／尚未接通的方式顯示**：通過獨立身份、安全、使用條款、資料權限與沙盒驗證前，不能把規劃狀態改成真正在線。
- **不在公開前端儲存憑證或專有執行規則**：用受權限限制的後端存放機密；此版不需要也不接收 API Key。

## 2. 每個方向可以分別訂製什麼？

| 設定 | 接收（Inbound） | 送出（Outbound） |
|---|---|---|
| 資料格式 | 回報、證據、事件或自訂對應 | 任務、事件或研究資料 |
| 允許事件 | 結果、拒絕、修正、狀態等 | 任務、詢問、修正、反饋等 |
| 欄位映射 | 外部 ID → 主腦任務 ID | 主腦任務 ID → 外部請求 ID |
| 來源審核 | 驗證回報身分與關聯 | 檢查來源及可分享範圍 |
| 核准 | 先隔離待審，再決定是否入記憶 | 先人工批准，再進行實際傳輸 |
| 回執 | 回報是否被本系統記錄 | 對方是否真的收到（需正式通道證明） |
| 失敗策略 | 隔離、保留或提示 | 隔離、保留或提示 |
| 上限 | 1–256 KB 的規格限制（預設 64 KB） | 同左；可分別調整 |
| 重試 | 自訂次數與退避時間，現階段未執行 | 現階段人工流程固定不重試 |

**保護門檻：** 進站／送出的 HTTPS 與 Webhook 可以選來規劃，但目前不能透過使用者自行勾選就啟動真實連線。人工流程啟用仍不代表三個 AI 自動收到資料。

## 3. 一筆資料往返會發生什麼？

| 階段 | 平台顯示 | 真正意思 |
|---|---|---|
| 建立 | 草稿／已驗證格式 | 尚未送出 |
| 排隊 | 等待執行 | 待授權或調度 |
| 發送 | 已送出 | 不代表收件 |
| 回執 | 已接收 | 必須來自經驗證的收件身份 |
| 處理 | 執行中 | 尚未交付結果 |
| 完成 | 已處理 | 不代表內容正確 |
| 人工審批 | 已核准或拒絕 | 將資料加入經核准版本或保留反例 |
| 停止 | 已請求停止／已確認停止 | 「要求停止」和「真正停止」不同；專案聊天仍可繼續 |

每筆紀錄都保留 `message_id`、`correlation_id`、`project_id`、`task_id`、`connector_id`、傳輸方向、時間、資料版本與來源查核結果。未確認來源的回報隔離，不冒充模型已完成的回覆。

## 4. 可以在哪裡設定？

- `connector-studio.html`：同一畫面設置接收／送出、接口命名、欄位對應、驗證與審批、事件類型、最大單筆大小、失敗策略；支援 **GPT①／GPT②／BOT③／自訂新接口**。
- 可按「檢查雙向規格」驗證配置，或用虛構訊息「模擬進站與送出」，再下載 JSON。示範會特別拒絕未驗證的外部回執。
- 主腦控制台、發射器、架構圖均有進入「雙向接口訂製」的入口。
- 未來實際 API 存活測試、連線健康狀態與使用限制應來自後端監控，不能依使用者自行勾選的狀態推測。

## 5. 自己的 API 規格（草稿）

`supabase/functions/brain-api/index.ts` 提供未部署的、需 Supabase 身份驗證的 API 路由：

| 方法 | 路徑 | 作用 |
|---|---|---|
| GET | `/v1/overview` | 取得共用規格與入口狀態 |
| GET／POST | `/v1/projects` | 查詢、新建專案 |
| PATCH | `/v1/projects/:id/settings` | 共用提醒、圖片、介面設定 |
| GET／POST | `/v1/conversations` | 專案對話，停止任務不影響對話 |
| GET／POST | `/v1/tasks` | 任務、狀態與已保存進度 |
| POST | `/v1/tasks/:id/stop` | 保存停止請求、留下事件 |
| POST | `/v1/tasks/:id/refuse` | 保存拒絕原因、影響和下一步，向操作端返回提醒內容 |
| GET | `/v1/events?project_id=...` | 雙向紀錄／修正／拒絕歷史 |
| GET／POST | `/v1/connectors` | 列出／新增規劃中的接口身份與能力 |
| GET | `/v1/connectors/template` | 取得雙向訂製的預設規格 |
| POST | `/v1/connectors/validate` | 驗證雙向規格，不寫入正式接口 |
| POST | `/v1/transfers/preview` | 只做傳輸預檢，**不發送請求** |

共用的 API 規則在 `supabase/functions/_shared/tcvl-api-core.mjs` 和 `tcvl-transfer-contract.mjs`，正式執行需透過 Supabase JWT、權限與隔離的專案資料庫。

資料庫初稿在 `supabase/migrations/202610150001_tcvl_platform_api_v1.sql`；包含 per-user RLS、審計、停止及拒絕 RPC，**沒有套用到任何實際資料庫**。本版僅保存連接器**基本資訊**；完整雙向訂製 manifest 目前由前端下載 JSON，不會在遠端自動持久化。
