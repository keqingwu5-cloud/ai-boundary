# 第一大腦｜開源工具評估 V0.1（研究分支）

**狀態：RESEARCH / ISOLATED / NOT_APPROVED / NOT_DEPLOYED**  
查核日期：2026-11-09  
基礎：Draft PR #138 HEAD `a8f255b443cf0ec120be6dad39758f7d3a4e02e3`

## 評估範圍

依使用者規則執行「需求分析 → 關鍵字搜尋 → 開源比較 → 相容性驗證」。

### 1. Ajv（JSON Schema 驗證）

- **授權**：MIT
- **最近維護**：主動（8.x 系列，支援 Draft 2020-12）
- **Node.js 相容**：≥18
- **依賴成本**：中等（編譯器大小 ~30KB+ gzip，需 package.json + npm ci）
- **與現有契約整合**：現有 `schemas/*.preview.schema.json` 可直接使用；可取代部分手動 `exact()` 檢查
- **決策**：暫不引入。理由：倉庫目前無 package.json，CI 為純 `node *.mjs`；手動契約檢查已覆蓋關鍵路徑；引入會增加供應鏈與建構成本。保留為後續候選（若需規模驗證或跨語言 schema 共享）。
- **淘汰理由**：依賴成本高於當前隔離研究收益；現有手動檢查已足夠防住已知洞。

### 2. fast-check（屬性測試 / 自動化負例）

- **授權**：MIT
- **最近維護**：主動（4.x，Node ≥12）
- **Node.js 相容**：良好
- **依賴成本**：低（devDependency），但需引入測試跑者整合
- **與現有契約整合**：可補強現有手寫負例（已有 25+ 項），產生随機輸入測不變式
- **決策**：暫不引入。理由：現有手寫負例已覆蓋主要邊界（NaN、Infinity、版本衝突、過期證明）；引入需更新 CI workflow 與 package.json。保留為後續自動化拓展候選。
- **淘汰理由**：當前合成資料負例已足够；屬性測試的額外收益未超過引入成本。

### 3. json-schema-to-typescript（減少跨 AI 欄位不一致）

- **授權**：MIT
- **最近維護**：主動（15.x / 16.x）
- **Node.js 相容**：良好（16.x 需 Node 22+ 或使用 15.x）
- **依賴成本**：低（生成工具，非運行依賴）
- **與現有契約整合**：可從現有 schema 生成 `.d.ts` 作為跨端參考，減少手動欄位漂移
- **決策**：暫不引入為建構依賴。可離線使用生成參考型別；倉庫目前為純 JS，無 TS 編譯步驟。
- **淘汰理由**：運行時不需要；生成工具可在研究階段外部執行。

### 4. Pino（日誌）

- **狀態**：暫列後續候選，不急著加入。
- **理由**：現有四類日誌為引用 + digest，不寫全文；Pino 為結構化日誌，可作為未來持久化或外部觀察層候選。

## 決策原則

- 優先重用成熟、輕量、可驗證工具。
- 不因熱門就安裝；比較至少兩種方案（含「不新增依賴，使用現有程式」）。
- 本輪選擇「不新增依賴」：以現有手動契約 + 負例測試 + schema 檢查為主，保持隔離分支輕量。
