# 主腦控制台 × 專案治理：目前已接上的部分與真正尚缺的接口

## 原因

單純把發射器、回溯、架構、專案治理做成不同網頁，仍然會造成工作脈絡被分開：使用者轉頁後無法知道任務是否仍在進行，或者必須自行交接最新進度。

使用者希望保留**現行工作節點**與**未來規劃節點**兩類，也要求「停止指定工作而對話不中斷」、「拒絕即時提醒」、「狀態選項全站一致」。

## 本草稿目前真正做到的事

- `mainbrain.html#workspace` 已新增「專案工作台」分頁，內嵌 `governance-board.html`。
- 主腦的頂端導覽加入專案治理、架構圖和回溯入口。
- 共用導覽列新增「主腦首頁」並導向專案工作台，讓使用者從架構、任務、記憶等頁面快速返回。
- 同一主腦頁面切換分頁時，內嵌專案頁面的暫存狀態仍存在；**離開、關閉或重新整理仍可能遺失，必須先匯出 JSON**。
- 目前專案治理頁有工作節點與候選規劃節點、人工對話、人工停止／恢復任務、拒絕與阻塞的原因／影響／下一步提醒，並可匯出符合現有記憶候選格式的資料。
- 僅圖片顯示設定和自訂狀態名稱透過同源本機 `localStorage` 跨頁共用；不在這個公開設定儲存器寫入聊天、密碼、API Key、專案目標或私人記憶。

## 仍然沒有連接到「AI 主腦」的部分

- 普通 GitHub Pages 超連結、內嵌網頁或共用導覽欄，不會讓 ChatGPT 對話、GPT①、GPT②、BOT③ 自動收發資料。
- 在專案頁打的訊息是**人工記錄**，不是自動 AI 聊天。
- 「停止指定工作」只更改本頁任務的狀態，不會取消已發出去的遠端模型要求或中斷其他服務。
- 回報狀態不可把「已複製／已分享」當成「遠端已接收」。
- 主腦當前本機加密記憶庫沒有自動同步成後端專案資料庫，也沒有跨裝置協作。

## 下一階段：真正安全的 AI／主腦橋接

建議沿用 TCVL-01 雙向治理，逐項建立：

1. **經驗證的專案身分與授權**：在私人後端建立 Project ID、Task ID、Thread ID、資料來源與操作者權限；前端不存放 API 金鑰。
2. **不可混淆的任務事件**：`draft`（草稿）、`queued`（待送）、`sent`（傳送請求）、`received`（服務端回執）、`running`（運行中）、`paused`（暫停／取消請求）、`reported`（收到成果）、`validated`（驗證完成）、`approved`（人工核准）。不能用 UI 狀態猜測真實遠端狀態。
3. **模型接口適配器**：為不同 AI 提供明確的輸入與輸出契約，保存訊息 ID、回覆 ID、版本、時間與工作結果，不在公開網頁呼叫秘密接口。
4. **真正的停止機制**：若服務商支援取消，向後端提交指定執行的取消請求，並等待取消確認；如果不支援，明確告訴使用者「已要求停止／尚未收到取消確認」。不可把本機暫停等同遠端停止。
5. **對話與任務獨立**：任務狀態轉成 `paused` 不應阻止專案對話追加訊息或改變目標；恢復工作必須要求使用者再次核准。
6. **事件／拒絕通知**：只有真正收到已驗證事件才在主腦平台提醒原因、影響、下一步；先前看不到的離線事件需在回連後補齊，不能假裝已被即時偵測到。
7. **記憶候選與核准**：自動回報最多寫入候選層，不能略過人類核准覆寫權威記憶。
